# 2602.17155 — Powering Up Zeroth-Order Training via Subspace Gradient Orthogonalization (ZO-Muon)

## 1. Citation

- **Authors:** Yicheng Lang, Changsheng Wang, Yihua Zhang, Mingyi Hong, Zheng Zhang, Wotao Yin,
  Sijia Liu (Michigan State, U. Minnesota, UCSB, Alibaba DAMO, IBM Research)

## 2. Summary

Plain randomized gradient estimation (RGE, MeZO-style) has variance proportional to the full matrix
dimension `m·n`. ZO-Muon combines two ideas, one per matrix.
(i) **Subspace RGE:** restrict the perturbation to a random r-dimensional column subspace `P`
(`m×r`, orthonormal, resampled lazily every v = 100 steps). The finite-difference estimate then
lives in a small `r×n` "core", which cuts the estimation dimension from `mn` to `rn`. Lifted back,
it estimates the *projected* gradient `P P^T ∇f`.
(ii) **Muon-style gradient orthogonalisation:** apply the matrix sign `msign(G) = U V^T` to the
*small core* before lifting, so the update is `X ← X − η P msign(Ĝ_Z)`.
Applying msign to a full-space ZO estimate (ZO-Muon-V0) is *worse* than MeZO, because whitening
amplifies noise directions. It only helps once the estimate is low-dimensional and averaged over
`Nq > 1` queries. With Nq = 1, msign of `s·Ψ` discards the magnitude and the sign is all that
survives. In fine-tuning (OPT-1.3B/13B, LLaMA3-8B, Gemma2-2B, ViT-B/L) it beats MeZO, LOZO,
SubZero, HiZOO, S-MeZO and FZOO at equal query budget, using about 25 % of MeZO's queries to reach
the same SST-2 accuracy.

## 3. Algorithm

### Symbols
- `X ∈ R^{m×n}`: one weight matrix (layer-wise, `{X_l}`). In PyTorch `Linear.weight` is `[out, in]`,
  so `m = out_features` and `P` acts on the **output** side.
- `f(X)`: minibatch loss to **minimise**.
- `P ∈ R^{m×r}`: column-orthonormal (`P^T P = I_r`), the Q factor of the QR decomposition of an
  `m×r` Gaussian matrix. Resampled every `v` steps ("lazy").
- `Ψ_i ∈ R^{r×n}`: iid N(0,1) entries. `i = 1..Nq` queries.
- `μ`: smoothing/perturbation scale. `η`: learning rate.
- `msign(G) = G (G^T G)^{-1/2} = U V^T` (thin SVD, all nonzero singular values set to 1).

### Subspace RGE (forward difference, eq 5–6)
```
s_i      = [ f(X + μ P Ψ_i) − f(X) ] / μ            # Nq perturbed forwards + 1 clean forward
Ĝ_Z      = (1/Nq) Σ_i s_i Ψ_i                       # r×n core: estimate of P^T ∇f (smoothed)
Ĝ_X      = P Ĝ_Z                                    # "Subspace-MeZO": estimate of P P^T ∇f
```
They use forward differences when `Nq > 1` (`Nq + 1` queries per step, one shared clean loss) and
central differences when `Nq = 1`. All matrices are perturbed **simultaneously** in each query,
MeZO-style, with seed-regenerated noise. Each matrix has its own `P_l` and `Ψ_{i,l}`.

### ZO-Muon update (eq 10)
```
O_t      = P msign( Ĝ_Z )                           # orthogonalise in the r×n subspace, lift
X_{t+1}  = X_t − η O_t
```
There is **no momentum** in the published update. First-order interpretation:
`O = P msign(P^T G)`. If `P` spans the top-k left singular vectors of G, this equals `msign(G)`
exactly (Prop. 1), so ZO-Muon approximates "low-rank Muon".

### Algorithm 1 (paraphrased)
```
init P_l = QR(randn(m_l, r)).Q for each matrix l
for t in 0..T-1:
    if t > 0 and t % v == 0: resample all P_l
    batch = next minibatch
    f0 = f(X; batch)                                          # clean
    for i in 1..Nq:
        Ψ_{i,l} ~ N(0,1)^{r×n_l} for each l (from seed)
        s_i = (f(X_l + μ P_l Ψ_{i,l} ∀l; batch) − f0) / μ
    for each matrix l:
        C_l = (1/Nq) Σ_i s_i Ψ_{i,l}
        X_l −= η · P_l · msign(C_l)                           # NS iterations or exact SVD
non-matrix params (vectors, embedding, output layer): MeZO update
```
msign is computed by Newton–Schulz by default. Exact SVD is affordable because the core is only
`r×n`: it is more accurate (OPT-1.3B SST-2 85.6 vs 83.5; OPT-13B 78.1 vs 72.5) but the msign step
is about 3× slower. The paper does not state the NS coefficients, the step count or a Muon-style
shape scale. Assume Muon defaults: 5 quintic steps, `(a,b,c) = (3.4445, −4.7750, 2.0315)`,
`X ← X/||X||_F` first.

### Theory (App. F)
With fixed P, Assumption 2 (`||P^T ∇f||_F ≥ δ ||∇f||_F`), `η = sqrt(2Δ/(L r T))` and
`μ = 1/(L sqrt(r n T))`:
`(1/T) Σ ||∇f(X_t)||_F ≤ O((1/δ) sqrt(r/T))`.
The trade-off: a 1/δ penalty for the missing gradient fraction, in exchange for a dependence on r
instead of m. Note that for a *random* P, `E||P^T G||^2 = (r/m) ||G||^2`, so δ is about `sqrt(r/m)`
unless gradients are genuinely low-rank.

### Hyperparameters (Sec. 5.1, App. H, Table A1)
| item | LLM | ViT |
|---|---|---|
| rank r | {64, 128} grid (64 typically best; 256 unstable late) | 64 |
| queries Nq | 4 (grid {4, 8, 16}) | 16 |
| lr η | 1e-2 constant, no weight decay | 1e-2 |
| μ | 1e-3 | 1e-3 |
| resample interval v | 100 (v = 1 worse; v = 500 about equal) | 100 |
| steps | 8k at Nq = 4, 4k at Nq = 8 (equal query budget 40k) | 10k at Nq = 4, 2k at Nq = 16 |
| batch | 16 | 64 (CIFAR-10), 256 (CIFAR-100) |
| data | 1,000 train / 1,000 test examples per task, MeZO prompts | CIFAR-10/100 |
| hardware | 1× A6000 48 GB | |

Baseline settings: MeZO lr ∈ {1e-7, 1e-6} (LLM). LOZO r ∈ {2, 4, 8}, v = 100. SubZero r ∈ {24, 48},
v = 1000. S-MeZO sparsity 0.8. Subspace-MeZO lr 1e-5, r ∈ {64, 128}.

Ablations:
- Data-informed P (Gaussian sketch of a ZO-momentum matrix) gives **no gain** over random P and
  adds memory.
- Nq > 1 hurts Subspace-MeZO (the "multi-query paradox") but helps ZO-Muon.

## 5. Classification for Crowd v1.5

**Complement to DUST.** It provides an estimator restriction and a coordinator-side update rule,
and maps almost one-to-one onto DUST's structure. DUST adds noise `σ a_t` to each layer's
**output** (`m = out_features`) and estimates `G_W = (1/(σ·tokens)) Σ_t reward_t a_t x_t^T`.
Restricting the activation noise to a shared random subspace, `a_t = P ψ_t` with `ψ_t ∈ R^r`,
gives `G_W = P · C`, `C = (1/(σ·tokens)) Σ_t reward_t ψ_t x_t^T ∈ R^{r×n}`. That is exactly
ZO-Muon's left projector.

DUST shortcomings it addresses:
- **Low gradient cosine / high variance:** the per-token noise dimension drops from m to r. The
  estimate targets `P P^T g`, which is biased, but variance falls by roughly m/r. Note that the
  cosine to the **full** gradient is capped near `sqrt(r/m)` per round under random P. The win must
  show up in *loss*, not in raw cosine.
- **Instability / divergence with relative sigma:** msign discards the estimate's scale. The step
  has spectral norm exactly η and Frobenius norm ≤ η·sqrt(r), whatever sigma did to the magnitude.
  That is a hard step-size bound for free.
- **Communication bytes:** clients upload only `C` (`r×n`). `P` comes from a shared per-epoch seed
  (resample every v ≈ 100 rounds). That is an m/r reduction, 4–16× at m = 1024–2048, r = 128,
  composable with the 1-bit codec. The coordinator averages `C` across clients (linear, same P),
  then applies `P msign(mean C)`.
- **Byzantine peers:** msign after aggregation bounds the global step size. A single outlier client
  can still rotate the *direction*, so this is only a partial defence. It pairs with the median norm
  cap item in `research/README.md`.
- **Memory:** neutral to positive. There is no optimizer state, and msign costs one `r×n` SVD per
  matrix at the coordinator.

## 6. MVP recipe (M5 Max, MPS, about 2–10 min)

Model: 10m preset GPT, `context_length=128` (about 7M parameters, d = 256, MLP hidden about 4×),
FineWeb-Edu tokens. Ranks to try: r ∈ {16, 32, 64} (64 = m/4 for 256-wide matrices). The paper's r
was ≪ m at 2048–5120 wide.

**Experiment A: estimator quality (about 2 min).** On a checkpoint after about 200 Adam steps with
a fixed batch, compare at equal forwards (K = 64):
- (a) DUST as is;
- (b) **DUST-subspace**, with noise `σ P_l ψ_t`;
- (c) MeZO weight-space RGE;
- (d) weight-space Subspace RGE.

Measure (1) cosine to the backprop `g`, (2) cosine to the projected target `P P^T g`, and (3) the
one-step loss decrease after applying `−η P msign(C)` vs `−η·Ĝ` with η line-searched on a second
batch. **Proves out if** the msign+subspace step gives a larger one-step held-out decrease than
DUST's raw step at the best η for each, even though (1) is lower.

**Experiment B: training (about 8 min).** Run four arms, each with 4 simulated workers sharing
`P` per window of v rounds; every worker uploads `C` and the coordinator averages:
- (i) Adam backprop;
- (ii) DUST + current outer SGD/momentum;
- (iii) DUST-subspace + raw `P·mean(C)` (Subspace-MeZO analogue);
- (iv) **DUST-subspace + `P msign(mean C)`** (ZO-Muon analogue).

Sweep η ∈ {3e-3, 1e-2, 3e-2} with no momentum first. Then try momentum on the lifted `O_t`, which is
not in the paper, and v ∈ {20, 100}. Log loss vs tokens, vs wall time, and vs **uploaded bytes**.
**Proves out if** (iv) < (iii) and (iv) ≤ (ii) in held-out loss at equal tokens, with m/r fewer
bytes. Also check that (iv) never diverges across sigma_rel ∈ {0.003, 0.01, 0.03}, where DUST with
relative sigma is fragile.

Minimal pieces:
- `P_l` from a seeded QR every v rounds (`torch.linalg.qr` on CPU, then move to MPS).
- Noise hook `noise = (ψ @ P_l.T)`, where ψ is `[draws, B, T, r]`, reusing `Perturb.noise` in
  `crowd_v15/model.py`.
- A `C` accumulator: `ψ^T x` replaces `a^T x` in `dust_gradients`.
- `msign` via `U, S, Vh = torch.linalg.svd(C, full_matrices=False); U @ Vh`. SVD is cheap at `r×n`.
  MPS SVD may fall back to CPU, which is fine at this size.
- Embedding, head and norm gains keep DUST's current treatment (the paper uses MeZO for non-matrix
  and input/output layers).

## 7. Caveats / what is unclear

- **Fine-tuning only.** Its own limitations say "extending ZO-Muon to full pretraining ... remains
  open". The motivation, low-rank FO gradients (Fig. 3a: effective rank 60–108 at 99.99 % energy),
  was measured during fine-tuning. Pretraining gradients from scratch are likely higher rank, so
  random-P alignment δ ≈ sqrt(r/m) is the honest expectation.
- **The update magnitude is fixed.** `η·P·msign` with constant η = 1e-2 means no natural annealing
  near convergence. The paper uses a constant lr for 8k steps. Pretraining will need a schedule.
- Newton–Schulz settings (coefficients, step count, shape scale `sqrt(max(1, m/n))`) are not given.
  How non-matrix parameters (and the embedding/head) are handled is only "with MeZO", with no stated
  lr.
- The "multi-query paradox" claim (Nq > 1 hurts Subspace-MeZO) is shown on ViT-B CIFAR-100 only.
  Its mechanism, if it is real, matters for DUST's population averaging.
- Query accounting uses forward differences (`Nq+1` forwards/step) against MeZO's central
  differences. Compare by forwards, not "queries", when reproducing.
- The cross-client version needs every client in a round to use the **same P**, and msign is
  nonlinear. Average `C` first, then apply msign at the coordinator. Applying msign per client and
  then averaging is a different, untested estimator.
- Biased target `P P^T g`: momentum or error feedback across P-resamples is untested here. Lazy
  resampling (v = 100) is what they found stable; v = 1 was worse.
