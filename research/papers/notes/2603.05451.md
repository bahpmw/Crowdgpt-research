# 2603.05451 — FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling (FA4)

## 1. Citation

- **Title:** FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling
- **Authors:** Ted Zadouri*, Markus Hoehnerbach*, Jay Shah*, Timmy Liu, Vijay Thakkar, Tri Dao (*equal
  contribution). Princeton University, Meta, Colfax Research, NVIDIA, Georgia Tech, Together AI.
- **Date:** arXiv v1, 5 Mar 2026 (cs.CL). No venue stated.
- **Code:** https://github.com/Dao-AILab/flash-attention/tree/main/flash_attn/cute. The paper says it uses a
  permissive license; we did not check the repo.

## 2. Summary

FA4 is a new exact-attention kernel (forward and backward) for NVIDIA's datacenter Blackwell GPUs (B200/GB200).
Blackwell doubled BF16 tensor-core throughput versus H100 (8,192 vs 4,096 ops/clock per streaming multiprocessor,
SM). The exponential unit (MUFU, 16 ops/clock/SM) and shared-memory (SMEM) bandwidth (128 B/clock/SM) did not
scale. As a result, softmax exponentials and SMEM traffic, not matrix multiplies (MMA), now bound attention. FA4
co-designs the algorithm and the kernel around this:
- fully asynchronous MMAs that write to the new 256 KB per-SM tensor memory (TMEM);
- software-emulated exp2 on the fused multiply-add (FMA) units, plus conditional softmax rescaling;
- a backward pass that uses TMEM and the paired-block (2-CTA) MMA mode to cut SMEM traffic and halve atomic adds;
- longest-processing-time-first (LPT) tile scheduling;
- a deterministic backward mode.
It is written entirely in CuTe-DSL (Python) and compiles 20–30× faster than FlashAttention-3's C++ templates.

## 3. Method

- **Forward roofline (Sec 3.1.1, Table 1):** a 128×128×128 tile costs 1,024 cycles of MMA, 768 of SMEM and 1,024
  of exp. A 256×128×128 tile costs 2,048 / 1,536 / 2,048. The exp unit ties the tensor cores.
- **Pipeline (Sec 3.1.2):** each thread block computes two output tiles in a ping-pong schedule. Two softmax
  warpgroups (one thread per row), one "correction" warpgroup for output rescaling, and one warpgroup that issues
  MMA and memory loads. P goes through TMEM, so rescaling is off the critical path.
- **Exp emulation (Sec 3.1.3, Table 2):** 2^x = 2^⌊x⌋ · 2^frac. The integer part is done with exponent-bit
  arithmetic; the fraction uses a polynomial evaluated with FMAs.
  - It is applied to only 10–25% of each row, so register pressure stays low.
  - A degree-3 polynomial has max relative error 8.77e-5 in FP32, but after BF16 rounding it is indistinguishable
    from hardware (3.90e-3 vs 3.89e-3). It is within 1 BF16 ULP of the hardware result on 99% of inputs.
- **Conditional rescaling (Sec 3.1.4, Eq. 6):** rescale the running output only when the row max grows by more than
  τ = log2(256) = 8. The final division by the true max and sum keeps the result exact. To avoid divergence, a warp
  rescales if any of its threads needs it.
- **Backward (Sec 3.2, Table 3):** with 1-CTA tiles (M=128), SMEM takes 3,328 cycles against 2,560 for MMA (+30%).
  2-CTA MMA (M=256) cuts SMEM to 2,688 cycles (+5%). The two blocks exchange half of dS through distributed shared
  memory, so each block does half the dQ global atomic adds.
- **Deterministic backward (Sec 3.2.4):** global reductions are serialized with a semaphore in a fixed order. For
  causal masks a "shortest-processing-time-first" (SPT) order keeps blocks from stalling on their first dQ write.
- **Scheduling (Sec 3.3):** LPT order with batches outermost and heads swizzled in L2-sized sections. Variable-length
  batches are sorted by a preprocessing kernel.

## 4. Key reported results

- **Forward (Sec 5.1, Fig. 4–5; B200, BF16, head dim 128, seq 1k–32k, 32k tokens per batch):** 1.1–1.3× faster
  than cuDNN 9.13 and 2.1–2.7× faster than Triton. Peak 1,613 TFLOPS, about 71% of theoretical. Gains are largest
  for causal masks, which the authors credit to LPT scheduling.
- **Backward (Sec 5.2, Fig. 6–8):** consistent speedups at long sequences. **The deterministic backward reaches up
  to 75% of the speed of the non-deterministic 1-CTA backward** (Fig. 7).
- **LPT on Hopper (Sec 3.3):** +4–8% FLOPS for multi-head attention and +7–14% for multi-query attention (printed as
  "MQA 8"), on H200 with FA3 (BF16, head dim 128). This shows the scheduling idea is not Blackwell-specific.
- **Compile time (Table 4):** FA3 takes 55 s (forward) / 45 s (backward); FA4 takes 2.5 s / 1.4 s, i.e. 22× / 32×.
- **Diffusion into vendor libraries:** cuDNN 9.13/9.14+ adopted FA4 techniques and newer cuDNN versions perform
  similarly (Fig. 4 caption, App. A.1).
- FA3 does not run on B200 (footnote, Sec 5).

## 5. Relevance to Crowd

- **No direct use on volunteer hardware.** FA4's main path needs TMEM, asynchronous tcgen05 MMA and 2-CTA MMA.
  These are datacenter Blackwell (SM100) features, so the main path cannot run on our fleet. The paper itself says
  low-precision kernels such as SageAttention target consumer GPUs, and it chose not to.
  - Consumer cards (RTX 3090 = Ampere, 4060 Ti/4090 = Ada, 5090 = consumer Blackwell SM120) still use
    FlashAttention-2-class or vendor kernels. So does Apple silicon (Metal).
  - A third-party SM120 port's README on Hugging Face (SecondNatureComputing/flash-attn-4-sm120) says SM120 has
    no tcgen05/TMEM and about 99 KB of SMEM, so FA4's primary speed path does not apply. We saw this only in a
    search snippet; it is unverified.
- **Ideas that do transfer.**
  - LPT scheduling is architecture-neutral (shown on H200).
  - Conditional rescaling is pure algorithm and fits any FlashAttention-style kernel (Triton, Metal).
  - FMA-based exp helps wherever the exp unit, not the tensor cores, is the bottleneck. Whether consumer cards are
    exp-bound is not measured here (unverified).
- **How much attention matters at our sizes (our estimate, not from the paper).** Using the paper's FLOP convention
  (4·s²·d_head·heads forward, halved for causal masks), causal attention scores add about s/(12·d) of a dense
  layer's FLOPs. At d = 2048 that is about 8% at s = 2k, 17% at 4k and 130% at 32k. Kernel speed matters most in
  long-context phases.
- **Heterogeneous fleets.** On the same GPU, attention speed varies 2–3× by implementation (FA4 vs Triton). If Crowd
  ever mixes datacenter peers (Covenant-72B's peers are 8×B200 nodes, 2603.08163) with consumer peers, per-peer
  throughput will differ widely. That favors credit by verified tokens rather than time. It also favors
  asynchronous schemes in which learners never wait, as in Decoupled DiLoCo (2604.21428).
- **Bit-reproducibility and replay audits (important).**
  - The paper confirms that atomics make dQ (and dK/dV under grouped-query attention) nondeterministic by
    default, and that determinism costs up to ~25% of backward speed (Fig. 7).
  - It also shows that mixing emulated and hardware exp changes FP32 intermediates (relative error up to 8.8e-5),
    even though BF16 outputs match within 1 ULP on 99% of inputs.
  - Implications for Crowd's audits, which are reproducible only on the same device class (DEEPDIVE.md):
    (1) the audit contract must pin kernel, version and deterministic flag; (2) audits across device classes need
    tolerance-based checks, such as the cosine/loss thresholds Crowd already uses, not bit equality; (3) honest
    peers on different kernels will legitimately disagree in low bits.

## 6. Caveats

- Kernel microbenchmarks only: no end-to-end training throughput and no model-quality runs.
- One hardware family and BF16 only in this paper. Per-length numbers exist only in figures; we did not transcribe
  them.
- As printed, App. A.1 says benchmarks ran on a "B100 180GB SXM6 (1000W)" while the main text says B200. It also
  dates library versions to "March 2025", though CUDA 13.1 and PyTorch 2.10 suggest 2026. We could not resolve these.
- FA4's lead over cuDNN is temporary because cuDNN absorbed its techniques. Nothing on consumer GPUs, Apple, AMD,
  FP8/FP4, or how exp emulation affects training numerics.
