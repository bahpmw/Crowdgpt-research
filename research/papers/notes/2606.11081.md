# 2606.11081 — Unifying Local Communications and Local Updates for LLM Pretraining (GASLoC)

## 1. Citation
- **Title:** Unifying Local Communications and Local Updates for LLM Pretraining
- **Authors:** Pietro Cagnasso (Concordia University, Mila), Eugene Belilovsky* (Concordia University, Mila),
  Edouard Oyallon* (CNRS, Sorbonne University). *Equal contribution.
- **Date:** arXiv v1, 9 Jun 2026 (cs.LG), 38 pages, 9 figures. **Venue:** preprint with a NeurIPS checklist;
  acceptance unverified.
- **Code:** the checklist says code "will be released"; no link in v1.
- **Name:** GASLoC = Generalized Accelerated Sparse communication Local Computation (Sec. 3.1). It is the dense
  base that SPICE (2611.23053) sparsifies.

## 2. Summary
DiLoCo-style methods communicate rarely but still use a global all-reduce, which waits for the slowest link and
breaks when one link fails. GASLoC replaces the all-reduce with gossip:
- After H_i local AdamW steps, each worker exchanges its **full post-local parameters** with 1 or 2 peers. Peers
  come from a fresh random permutation each round.
- Each worker forms an outer pseudo-gradient (its own round-start parameters minus the mean of its neighbors'
  endpoints) and takes an outer Nesterov step.
- On the complete graph this is exactly DiLoCo.

The outer momentum doubles as gossip "acceleration": the consensus term improves from the spectral gap χ to √χ
(Lemma 1 in App. A; Prop. 2). Randomized 1- and 2-peer graphs have an expected spectral gap that does not grow
with the number of workers n (Prop. 1). Each worker may also choose its own number of local steps H_i, so a
worker on a slow link does fewer local steps instead of making everyone wait.

## 3. Method
- **Algorithm 1:** inner loop `y_i = AdamW^{H_i}(x_i)`. Neighbors N_i always include i. Outer step:
  `x_i ← OuterOpt(x_i, mean_{j∈N_i}(x_i − y_j))`.
- **SGD form (Eq. 1–2):** `x_{t+1} = x_t + ηg_t − αΛ(x_t + ηg_t) + γ[(x_t+ηg_t) − (x_{t−1}+ηg_{t−1})]`.
  Setting Λ = π (complete averaging) recovers DiLoCo.
- **Peer sampling (Sec. 3.2, App. B):**
  - 1-Peer: a random perfect matching taken from a random permutation.
  - 2-Peer: each worker talks to its 2 neighbors on the random ring.
  - Both satisfy `E[Λ] = n/(2(n−1))·π`; 2-Peer has lower variance (Prop. 1).
  - A fixed cycle would have χ growing like n², so it slows down with n.
- **Straggler rule (Sec. 3.2):**
  - All-reduce round time ≈ `max_i 2T_comm,i + max_i H_i·T_comp,i`.
  - GASLoC round time ≤ `max_i (k·T_comm,i + H_i·T_comp,i)` with k ≤ 2.
  - Choose H_i so that `T_comm,i + H_i·T_comp,i` is equal across workers.
  - Disjoint islands may run a small all-reduce internally.
- **Fault tolerance (Sec. 3.2):** a slow or failed exchange only affects its neighbors. This assumes failed
  exchanges are skipped or rescheduled; it is argued, not evaluated.
- **Convergence (Prop. 2):** a standard non-convex rate with a heterogeneous-H term (2Lηβσ²/n²)ΣH_i. It assumes
  homogeneous (IID) data and SGD inner and outer optimizers.
- **Setup (Sec. 4, App. B):**
  - Models: Llama-3-style 134M (12 layers, d = 768) on 2.7B FineWeb tokens; 551M (16 layers, d = 1536) on 11B.
  - Training: global batch 2M tokens split over n ∈ {8, 16, 32} workers; AdamW (0.9, 0.95), weight decay 0.1.
  - Outer tuning: learning rate probably {0.4, 0.6, 0.8, 1.0} (the extracted text is garbled), momentum
    {0.5, 0.7, 0.9}, plus a finer sweep.
  - Hardware: H100 nodes, with several logical workers per GPU.

## 4. Key reported results
- **One step per round (H = 1).**
  - 134M, 16 replicas (Table 1a): distributed data parallel (DDP) 3.18; GASLoC-2-Peer 3.22; DAdam (adaptive
    gossip baseline) on the complete graph 3.25; ring 3.36 (GASLoC) / 3.33 (DAdam). At matched 2-peer sampling,
    GASLoC beats DAdam by 0.06.
  - 551M, 16 replicas (Table 2): DDP 2.64; GASLoC-2-Peer 2.69; DAdam complete 2.70.
- **H = 30, 134M (Table 1b), loss for 8/16/32 replicas:**
  - DiLoCo 3.30/3.40/3.53; GASLoC on the complete graph 3.30/3.40/3.53 (identical, as the theory says).
  - GASLoC-2-Peer 3.32/3.45/3.62; 1-Peer 3.34/3.49/3.66; Local-DAdam 3.47–4.00.
- **H = 30, 551M (Table 3):** DiLoCo 2.64/2.67 (8/16 replicas); GASLoC-2-Peer 2.64/2.72; 1-Peer 2.67/2.81.
- **Bandwidth straggler (Sec. 4.2, Fig. 3):**
  - Setup: 8 nodes × A100, 134M, 1 Gbit/s links, one straggler at 100 or 200 Mbit/s. Bandwidth is simulated
    (the paper says it "simulates" these links).
  - The straggler runs H_i = 15 (1-Peer) or 1 (2-Peer) at 10% bandwidth, and H_i = 30 or 15 at 20%; the others
    run H = 30.
  - Both GASLoC variants reach DiLoCo's loss in much less wall-clock time. The exact speedup is only shown in a
    figure (not tabulated, so unverified).
- **H sweep (Fig. 4, 134M, 8 workers):** sparse GASLoC beats DiLoCo at H ≤ 5 and is slightly worse at H > 5,
  with the same trend in H.
- **Outer optimizer (Fig. 7):** Nesterov beats momentum SGD (SGDM), which beats plain SGD, as workers grow
  (checked up to 32). Outer hyperparameter sensitivity is similar to the complete graph (Fig. 8).
- **Simulated 70B utilization (App. F, Fig. 9).** Assumptions: 16 workers × 8 GPUs, 40% model FLOPs utilization
  (MFU), one straggler at 20% bandwidth. GASLoC-1-Peer passes 80% compute utilization from about 10 Gbit/s
  (2-Peer from about 20 Gbit/s); all-reduce baselines stay lower.
- One run per configuration, no error bars (checklist item 7).

## 5. Relevance to Crowd
- **Hub-free local training.** This is the first clean evidence that DiLoCo-quality local training runs with no
  hub and only 1–2 peer exchanges per round. It also gives the formal link "outer momentum = gossip
  acceleration".
- **Straggler rule.** The per-worker H_i is the simplest straggler rule we have seen for a volunteer fleet. In
  principle, a 20 Mbit/s home peer and a 1 Gbit/s peer finish a round together by doing different numbers of local
  steps, so nobody waits (tested only with one straggler). Compare Decoupled DiLoCo (2604.21428), which uses a
  central quorum, a grace window and token weights.
- **Scheduling.** Partners come from a random permutation that all workers agree on (SPICE derives it from a
  shared seed, App. B.1 of 2611.23053), so no scheduler is needed. Per-peer, per-round cost does not depend on n.
- **Mixing at scale.** Mixing across n peers still costs quality: at H = 30 the 2-peer gap to DiLoCo grows with n
  (+0.09 at 32 replicas, 134M; Table 1b). For 10^5–10^6 peers, expect a hierarchy: all-reduce inside LAN or
  cluster islands, gossip between islands (Sec. 3.2 allows this; our inference for Crowd).
- **Composes with:** SPICE sparsity plus error feedback (cuts message size); the β2 rule and whitening inner
  optimizers (2610.19064); overlap of the exchange with the next H steps (LACCO-style, untested).
- **Bandwidth (our arithmetic).** Full-model messages are about 2 GB per peer per round for a 1B model in bf16.
  On a 20 Mbit/s uplink that is about 13 min per peer, so rounds must be very long or messages sparse (SPICE).
- **Trust:**
  - Gossip removes the validator choke point, but also the place where Covenant's Gauntlet scores each
    contribution.
  - Because peers exchange full parameter vectors, a receiver can score a neighbor's endpoint directly before
    averaging (loss on a small held-out batch, distance from its own model). That gives a natural hook for
    per-peer validation and reputation.
  - Byzantine endpoints spread through the graph, and no defense is evaluated. Soft Throttling (2609.39357) is
    server-based; a gossip version is open.
- **Data.** Homogeneous IID data is assumed, so Crowd's data assignment must preserve that.
- **Relation to round 1.** It is an alternative to the central aggregation of Covenant-72B (2603.08163) and
  Decoupled DiLoCo. SOLO-style memory savings (2609.35440) could sit inside each replica (our inference).

## 6. Caveats
- **Scale.** Small: 134M/551M models, ≤ 32 replicas, about 20 tokens per parameter. The 2M-token global batch is
  fixed, so the local batch shrinks with n.
- **Quality at H = 30.** Sparse gossip loses ground as replicas grow: 3.62 vs 3.53 at 32 replicas (134M); 2.72 vs
  2.67 at 16 (551M).
- **Straggler test.** Only one slow worker, with simulated bandwidth, and wall-clock shown only in a figure.
  DiLoCo is modeled as an all-reduce, not as the object-store design Covenant used.
- **Untested.** Churn, joins, failed exchanges and Byzantine peers; also non-IID data.
- **Theory.** Assumes SGD; AdamW is used in practice.
- **Reproducibility.** Single seed, no error bars, code not yet released.
