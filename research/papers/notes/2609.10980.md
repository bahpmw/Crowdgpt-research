# 2609.10980 — EGGROLL, Unrolled (LOO-ROLL)

## 1. Citation

- **Title:** EGGROLL, Unrolled: Understanding and Improving Low-Rank Evolution Strategies at Scale
- **Authors:** Ege C. Kaya, Abolfazl Hashemi (Purdue University)
- **Date:** arXiv v2, 25 Sep 2026 (preprint, under review)
- **arXiv:** 2609.10980 [cs.LG]
- **Builds on:** EGGROLL (Sarkar et al., "Evolution Strategies at the Hyperscale", ICML 2026,
  arXiv 2511.16652). Code: a 37-line patch to the EGGROLL vLLM repo at commit `bcc215e`.

## 2. Summary

EGGROLL makes evolution strategies (ES) affordable for LLMs by perturbing every weight matrix
with a rank-r Gaussian product `E_r = (1/sqrt(r)) A B^T` (usually r = 1), so a whole population
shares the base weights and each member costs only two thin matmuls. This paper does two things.
(1) Theory: it derives the exact *finite-rank* mean field EGGROLL follows. It is a resolvent
`(I + (sigma^2/r) L)^{-1}` applied to the gradient of the smoothed objective. That field can be
nonconservative and can even make a strict optimum repelling, yet it is *exact on quadratics*.
The leading correction scales as `sigma^2/r`. The extra sampling variance of rank-1 over dense
Gaussian ES is `2(m+n+1)/r` on top of `mn+1`, which is only 0.098 % at width 4096. In practice
rank barely matters, but sigma matters a lot.
(2) Method: **LOO-ROLL** replaces EGGROLL's antithetic pair (two forwards per direction) with a
**leave-one-out baseline**: each member's fitness minus the mean fitness of the *other* members.
That is one forward per direction, it stays unbiased, and at equal forward count the estimator
MSE is about halved. Spending the saved forwards on more updates gives large matched-wall-time
gains in LLM post-training (GSM8K/MATH, 0.6B–14B).

## 3. Algorithm

### Symbols
- `W ∈ R^{m×n}`: one weight matrix (maps `x ∈ R^n` to `Wx ∈ R^m`). The network has blocks `W_q`,
  each perturbed independently.
- `f(W)`: fitness to **maximise** (reward, or `-loss` for next-token prediction).
- `sigma > 0`: perturbation radius, an absolute weight-space scale.
- `r`: perturbation rank (1 by default).
- `A = [a_1..a_r] ∈ R^{m×r}`, `B = [b_1..b_r] ∈ R^{n×r}`, entries iid N(0,1).
- `E_r = (1/sqrt(r)) A B^T`, which has `E[vec(E_r) vec(E_r)^T] = I_{mn}` (identity covariance).
- `N`: number of independent directions (population) per step.
- `alpha`: learning rate.

### Perturbed forward (the efficiency trick)
```
(W + sigma E_r) x = W x + (sigma / sqrt(r)) * A (B^T x)          # eq (2)
```
For r = 1 this is `W x + sigma * a * (b·x)`: per token, add the vector `a`, scaled by the scalar
`sigma * <b, x>`. A batched population of N members is tensors `a: [N, m]` and `b: [N, n]`. Then
`y[N,B,T,m] = x @ W^T + sigma * (x @ b[:, :, None])  * a[:, None, None, :]`. Directions are
regenerated from seeds, so nobody stores or sends `E`.

### EGGROLL estimator (antithetic baseline, what the released code uses)
```
g_anti = (1/N) Σ_s E_s * [ f(W + sigma E_s) - f(W - sigma E_s) ] / (2 sigma)      # eq (6)
```
This costs 2N forwards. It is unbiased for the mean field `g_{r,sigma}(W) = (1/sigma) E[E_r f(W + sigma E_r)]`.

### LOO-ROLL estimator (the contribution)
For iteration t, sample N ≥ 2 independent directions `E_{t,s}` and evaluate **once** each:
```
F_{t,s}      = f(W_t + sigma E_{t,s})                         # N forwards total
Fbar_{t,-s}  = (1/(N-1)) Σ_{j≠s} F_{t,j}                      # leave-one-out baseline
g_LOO        = (1/(N sigma)) Σ_s E_{t,s} (F_{t,s} - Fbar_{t,-s})    # eq (22)
```
Identity: `F_s - Fbar_{-s} = N (F_s - Fbar) / (N - 1)`, so only the population mean is needed.
The baseline is independent of `E_s`, so `E[g_LOO | history] = g_{r,sigma}(W_t)` (Prop. 5.1).
There is no clean (unperturbed) forward and no mirrored partner.

### Score standardisation (kept in practice)
The real implementation keeps EGGROLL's processing: per-prompt centring, plus division of every
member's score by one standard deviation computed from the same population (S > 0). Prop. G.1:
centring cancels exactly, and a common divisor only rescales the realised update. Cor. G.3:
the expected field shifts by O(1/N). The measured cosine between raw and standardised mean
updates is 0.99970 at N = 128, rank 1.

### Update
Gradient ascent on fitness: `W_{t+1} = W_t + alpha * g_LOO` (standardised scores). For a loss,
use `f = -loss`. The paper gives no optimizer state. It uses EGGROLL's plain update with
"seed-based reconstruction, layerwise updates, and weight synchronization".

### Pseudo-code (one step, all matrices)
```
seeds = rng(step)
for s in 1..N:                       # batched in one forward in practice
    for each matrix q: a_{s,q}, b_{s,q} = gaussian(seed_s, q)        # rank 1
    F[s] = fitness(model with W_q + sigma a_{s,q} b_{s,q}^T, same batch)
z  = (F - F.mean()) * N/(N-1)        # leave-one-out centring
z  = z / (F.std() + eps)             # EGGROLL standardisation (optional; rescale only)
for each matrix q:
    W_q += alpha/(N*sigma) * Σ_s z[s] * a_{s,q} b_{s,q}^T      # = alpha/(N sigma) * A_q diag(z) B_q^T
```
The update for each matrix is `A diag(z) B^T`: a rank ≤ N matrix defined by N scalars plus seeds.

### Variance facts (useful for tuning)
- Single direction, local affine model `f(W + sigma E) ≈ f(W) + sigma <G, E>`:
  `E||G_hat_N - G||^2 = (kappa_r / N) ||G||^2`, `kappa_r = mn + 1 + 2(m+n+1)/r` (Thm 4.1).
- LOO-ROLL: `E||g_LOO - G||^2 = [kappa_r/N + (d+1)/(N(N-1))] ||G||^2`, `d = mn` (Prop 5.2).
- At equal forwards (2N LOO directions vs N antithetic pairs):
  `MSE ratio = 1/2 + (d+1) / (2 kappa_r (2N-1))`, which tends to 1/2.
- Network level (Cor. E.3): `E||X - G||^2 = (D+1)||G||^2 + Σ_q 2(m_q+n_q+1)/r_q ||G_q||^2`, `D = Σ m_q n_q`.
  Relative variance therefore grows with the **total** parameter count D. ES is still dimension-bound.
- Quadratic stability: `E||W_T||^2 / ||W_0||^2 = [1 - 2 eta + eta^2 (1 + kappa_r/N)]^T`. With few
  directions, `kappa_r/N` alone can make a step size unstable (8×8, eta = 0.3, N = 16: rank 1 diverges).

### Hyperparameters used
| setting | value |
|---|---|
| rank r | 1 (rank 8 tested: no reliable gain, +12–25 % iteration time) |
| sigma (reward tasks) | 1e-3; raising it to 4e-3 cut mean reward by 70–100 % |
| sigma (next-token prediction) | 1e-2 at 0.6B/1.7B, 3e-3 at 8B |
| learning rate alpha | 2e-4 (reward runs); 4e-4 for 8B NTP |
| directions N | 128 (reward tasks), 32 (NTP); equal-evaluation runs double LOO's N |
| batch B (prompts) | 4–8 (reward), 4 (NTP) |
| updates | EGGROLL 80–200; LOO-ROLL 131–523 in the same wall time |
| hardware | 1× H100 80GB + 14 CPU cores (14B MATH: 2× H100) |
| LOO-ROLL-specific tuning | none: same lr, rank and sigma as EGGROLL |

Tried and **rejected** (Appendix E.1): rank extrapolation `(s g_s - r g_r)/(s - r)` (7.6–8.7×
the MSE at ranks (1,2)), and an SVRG-style reference-point control variate (no gain; worse on
1.7B NTP).

## 4. Key reported results

- **Estimator MSE, Qwen3-0.6B blocks (Table 1):** equal directions cost +5.2 % (N = 16) down to
  +0.8 % (N = 128). Equal evaluations give **−49.0 % to −50.1 %** for N = 16..128, matching eq (25).
- **Finite-rank audit:** for 16×16 attention blocks, MSE relative to dense ES is 1.264/1.127/1.089/1.028
  at r = 1/2/4/8, against predictions of 1.257/1.128/1.064/1.032. The cosine between the mean field
  (8,192 directions) and the backprop gradient is **0.980–0.984** at every rank.
- **Matched wall time, LOO-ROLL minus EGGROLL (Table 2, 5 paired seeds):**
  | model | task | equal evals | equal wall time |
  |---|---|---|---|
  | Qwen3-0.6B | GSM8K | −4.82 ± 4.87 | **+24.90 ± 2.38** (38.10 → 63.00 %) |
  | Qwen3-1.7B | MATH-500 | −0.08 ± 1.25 | **+12.20 ± 1.56** |
  | Qwen3-8B | GSM8K | −1.08 ± 1.21 | **+14.13 ± 0.88** (65.87 → 80.00 %) |
  | Qwen3-14B | MATH-500 | +0.60 ± 0.47 | **+8.08 ± 1.23** (44.68 → 52.76 %) |
  | SmolLM2-1.7B | Countdown | −0.08 ± 0.34 | −0.10 ± 0.46 |
  Of 14 settings, 11 are individually significant and 9 survive Holm correction. None favours EGGROLL.
- **Next-token prediction (Table 6):** held-out NLL at equal wall time is −0.55 % (0.6B),
  −1.20 % (1.7B) and −2.16 % (8B). At equal evaluations the difference is roughly zero, so the gain
  comes from **more updates**, not a better step.
- 14B MATH: LOO-ROLL completes 522.8 updates against EGGROLL's 200 in about 29 h.

## 5. Classification for Crowd v1.5

**Complement to DUST.** The LOO baseline drops straight into DUST's per-draw scoring. EGGROLL
rank-1 weight-space ES is a separate candidate *replacement*, covered in the caveats.

DUST shortcomings it addresses:
- **Compute cost per useful step (main one).** `crowd_v15/dust.py` scores each draw antithetically:
  `delta_t = (L+_t - L-_t)/2`, two perturbed passes per draw plus a clean pass. LOO-ROLL says to
  spend those passes on twice as many independent draws and centre with the leave-one-out mean
  instead. At equal forwards this predicts about half the estimator MSE. DUST's per-token
  `delta_t` and discounted reward-to-go become `delta_{s,t} = L_{s,t} - mean_{j≠s} L_{j,t}`, applied
  per token and per draw.
- **Low gradient cosine / high variance:** halving MSE at fixed compute is roughly a `sqrt(2)` gain in
  SNR. It does *not* fix dimension scaling (`kappa ∝ D`).
- **Communication (if adopting EGGROLL-style weight-space ES):** an update is
  `A diag(z) B^T` per matrix. A client that evaluated N members can upload **N fitness scalars**
  plus a seed instead of a gradient: about 4N bytes per round, against about 127 MB for `ngd1` at 1B.
- **Byzantine peers:** scalars are cheap to re-verify. The coordinator can re-run any member from
  its seed (as DUST's `noise_device="cpu"` already allows). The LOO baseline needs the whole
  population's mean, so the coordinator computes it after gathering. A lying client shifts every
  other member's baseline by `1/(N-1)` of its error, so a robust mean or median baseline is worth a
  small test.
- It does **not** address async/stragglers: the LOO baseline wants a synchronised population at the
  same `W_t`.

## 6. MVP recipe (M5 Max, MPS, about 2–10 min)

Model: `ModelConfig.preset("10m")` with `context_length=128` (vocab 4096, 6 layers, d = 256, about
7M parameters), real FineWeb-Edu tokens, a fixed held-out batch for evaluation.

**Experiment A: estimator quality at equal forward count (about 2 min, decisive).**
1. Take one checkpoint after about 200 Adam steps (fresh init gives misleading cosines). Fix one
   batch (B = 16, T = 128) and compute the backprop reference with `backprop_gradients` in
   `crowd_v15/dust.py`.
2. For a budget of `K ∈ {16, 32, 64, 128}` perturbed forwards, compute per-layer cosine to backprop
   for:
   - (a) DUST antithetic, K/2 draws (current code, `mode="all"`);
   - (b) **DUST-LOO**, K draws, one pass each, `delta_{s,t} = L_{s,t} - mean_{j≠s} L_{j,t}`, then
     DUST's `gamma` reward-to-go;
   - (c) EGGROLL-antithetic rank 1 in weight space, K/2 pairs;
   - (d) LOO-ROLL rank 1, K directions.
3. Report mean cosine, and MSE relative to `||g||^2` over 20 seeds. **Proves out if** (b) beats (a)
   and (d) beats (c) at every K, with an MSE ratio near 0.5–0.6 (cosine² up by about 1.7–2×).
   If (b) shows no gain, DUST's token-level pairing is already doing work the LOO baseline cannot,
   which is worth knowing too.

**Experiment B: training curves (about 8 min).** Same model. Arms: Adam backprop (lr 3e-3);
DUST antithetic (current config, population 32 → 64 passes); DUST-LOO (64 draws → 64 passes);
LOO-ROLL weight-space rank 1 (N = 64, sigma ∈ {1e-3, 3e-3, 1e-2}, z-scored fitness, plain SGD,
alpha swept over 3 values). Log held-out loss against tokens and against wall time. Use
sequence-mean loss as fitness for the weight-space arms.
**Proves out if** DUST-LOO reaches the antithetic arm's final loss in ≤ 60 % of the wall time.
For weight-space LOO-ROLL, the meaningful bar is whether it beats DUST at equal wall time at all.
Expect it not to on pretraining from scratch: variance grows with D, about 7M here.

Minimal pieces to implement:
- LOO centring function: about 5 lines.
- A rank-1 perturbed linear: `y = x@W.T + sigma*(x@b)[...,None]*a`, batched over a leading
  population axis.
- Seed-to-(a, b) generator.
- Update `W += alpha/(N sigma) * (a.T * z) @ b`.

## 7. Caveats / what is unclear

- **Post-training only.** Every LLM result starts from a pretrained Qwen3/SmolLM2 checkpoint, with
  80–523 updates. Nothing here shows ES pretraining from scratch working (compare
  2609.37899, where EGGROLL reproduction is the *worst* arm at 8.4M parameters).
- The gain is **matched wall time from more updates**. At equal evaluations, 13 of 14 comparisons
  are unresolved. If our bottleneck is upload rounds rather than forwards, the benefit shrinks.
- The optimizer is not specified beyond "EGGROLL's update". It is unclear whether the update divides
  by sigma after standardisation, and there is no mention of momentum, Adam or weight decay. The
  fitness-shaping details (rank vs z-score) are inherited from EGGROLL and not restated.
- The theory (unbiasedness, variance formulas) holds for the **unstandardised** estimator and a
  local affine model. Standardisation adds O(1/N) bias.
- The equal-directions MSE penalty (+5 % at N = 16) means LOO wins only when the extra directions
  are actually spent. For small N per client, set the baseline over the **global** population, not
  per client.
- LOO assumes all members see the **same batch**, or at least that batch effects are independent of
  `E_s`. Under DUST's per-token scoring, batch differences across clients would leak into the
  baseline. Centre per client batch, or share batches.
- Finite-rank results (nonconservative field, repelling optima) appear at `sigma^2/r` of order 1. That
  is irrelevant at sigma = 1e-3 but a warning for large relative sigma.
- DUST perturbs **activations**, not weights, so the paper's rank/resolvent theory does not transfer
  directly. Only the LOO baseline result (Prop. 5.1–5.2) is estimator-agnostic: it holds for any
  score-function estimator with independent, zero-mean directions.
