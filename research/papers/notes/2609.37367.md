# 2609.37367 — Backdoor Mitigation in Decentralized LLM Fine-Tuning (Chorus)

## 2. Summary

In decentralized fine-tuning, each node trains a low-rank adapter (LoRA), sends it to its graph neighbors
and averages what it receives (decentralized parallel stochastic gradient descent, D-PSGD). One malicious node that trains on
"trigger word → refusal" examples can backdoor honest nodes that never see a poisoned example. Undefended,
the attacker's neighbors reach a 48–63% average attack success rate (ASR), and the worst honest node reaches
78% (Fig. 2, Table 1). Existing defenses need things a peer does not have: a view of all updates, a clean
reference model, or labeled backdoored adapters. **Chorus** judges each received adapter by its
**behavior**, using the receiver's own adapter as the trusted reference. All receivers of the same adapter
pool their evidence and vote, so a backdoor that slips past one receiver is caught by the others. A
per-neighbor trust state machine ejects repeat offenders.

## 3. Method

Each round, every receiver i screens each incoming adapter θ_j with two tests (Algorithm 1, Table 4):

- **Stage 1a, probe and vote** (from ICLScan): P = 30 prompts from i's private probe pool, each with two
  normal demonstrations, one demonstration pairing a triggered instruction with a refusal, and a triggered
  query. Each node draws its own probe trigger from a public 10,000-word list and keeps it for the whole run;
  it need not match the attacker's trigger (App. C, E.5). Score = share of prompts on which θ_j refuses
  (18 refusal phrases, App. C). Receivers exchange scores. A strict majority above η = 25% rejects θ_j.
- **Stage 1b, harvest and movability test:** prompt θ_j with a compliant demonstration (nothing in context
  teaches refusal), decode with beam search (width 16, ≤48 tokens), keep word spans that recur across a
  10-round buffer (5 generations per round, spans ≥3 words seen in ≥2 generations). Receivers pool
  candidate strings, not verdicts. Movability Δ(θ, y) = average gain in per-token log-probability of y when
  y is shown in context versus not. A model that has memorized y barely moves. Reject if
  Δ(θ_j, y) / Δ(θ_i, y) < c = 0.1 for any of K = 4 candidates. A filter (ϕ = 0.5, with the longest string
  as reference) first drops generic phrases that i's own adapter has memorized too (§3.2.2, Algorithm 5).
- **Decision and trust:** reject if either stage rejects. TRUSTED → SUSPECTED after 2 consecutive
  rejections (stop merging); → EJECTED after 3 rejections within 5 rounds; ejected neighbors are re-checked
  every 10 rounds so an honest node can recover (App. A.3). Accepted adapters are averaged with equal weights.
- **Threat model** (§3.1): attackers know the attacker set, the graph and Chorus, but not honest data.
  Every neighborhood has an honest majority. Nodes know the graph up to distance two.

## 4. Key reported results

Setup (§4.1, App. C): 16 nodes on a 3-regular graph, 24 rounds, LoRA rank 8, non-IID data (not independent
and identically distributed; Dirichlet α = 0.1). One attacker poisons 15% (Alpaca) or 30% (Dolly-15k) of its
data. Models: Llama-2-7B-chat and Qwen3-8B. Three seeds.

- **Table 1, all four model–dataset settings:**

  | Method | Neighbor ASR | Attacker edges caught (true-positive rate, TPR) | Honest adapters rejected (false-positive rate, FPR) |
  |---|---|---|---|
  | No defense | 48.2–62.6% | — | — |
  | AlignIns (state-of-the-art baseline) | 0.2–23.0% | 75.0–96.8% | 34.3–37.3% |
  | Oracle (knows the attacker) | 0.0–1.7% | 100% | 0% |
  | **Chorus** | **0.0–2.2%** | **100%** | **0.1–4.7%** |

  Chorus's held-out loss stays within 0.012 of the oracle's. The worst honest node never exceeds 10% ASR in
  any round, the same bound as the oracle (Table 5).
- **Both stages are needed** (Table 2): probe only 90.3% TPR, movability only 91.8%, both 100%.
- **Harder attackers** (App. E, one seed each): 1 → 3 attackers, TPR stays 100% and ASR 2.78% → 2.04%,
  attackers ejected by round 5 (Table 6). A "merging" attacker that also averages its neighbors: TPR 100%,
  ASR 2.22% (Table 7). An adaptive attacker trained against the probe gets readmitted by Stage 1a at the
  round-15 re-check (scores 6.7%, 16.7%, 0%), but Stage 1b still rejects it: TPR 100%, ASR 2.22% (Table 8).
- **Trigger-agnostic:** the probe separates backdoored from clean adapters with all six probe words, even
  the control word "the" (60.0% vs 6.7% refusals, IID data) (Table 9). It detects in-context imitation of a
  refusal, not a specific trigger.
- **Separation:** attacker movability ratios ≤0.024 (108 measurements), honest ≥0.110 (4,008) (App. A.2,
  Fig. 7). Probe separation decays over training: the attacker's mean score falls from 93.3% (round 3) to
  46.7% (round 24) (App. E.4).
- **Cost** (§4.4): 3.0–4.1× wall-clock versus no defense; 73% of it is the beam-search harvest. Extra
  communication is 404 bytes per update, against adapters of 77–82 MB.
- Other detectors fail here: no trigger leakage in 586,120 generated characters (so trigger reconstruction
  fails); a supervised weight-space classifier catches the merging attacker in 0 of 22 cases (App. B.2).

## 5. Relevance to Crowd

- **Updates our v2 trust draft.** archived/crowdgpt-v2/02-trust-and-verification.md §6 says there was "no
  validated defence for decentralised LLM training as of Nov 2026". Chorus is one, for decentralized LLM
  fine-tuning, within its threat model.
- **Transferable principle** (our analysis): screen each contribution by its behavior, using the verifier's
  own model as the reference, with several randomly assigned verifiers pooling evidence. No shared
  validation set and no knowledge of the trigger are needed. In our layered design this sits between L3
  (usefulness score: LossScore/Gauntlet from Covenant-72B, 2603.08163) and L5 (fixed canaries after
  aggregation). It acts before a backdoor enters the global model. LossScore cannot see a backdoor because a
  poisoned update still lowers loss on clean data.
- **Patterns worth copying:** private, fixed per-verifier probe prompts, so an attacker cannot fit the test
  (the behavioral twin of our post-commit audit beacon); "share evidence, not verdicts", so a lying verifier
  can add candidate strings but cannot flip anyone else's decision; and a suspect → eject → re-check state
  machine that maps onto our probation and reputation and avoids permanently excluding honest peers.
- **Where it fits:** Crowd's post-training phases (instruction tuning or reinforcement learning at 9B–27B),
  and any gossip or multi-orchestrator lane where peers merge each other's updates. For base-model
  pretraining, Stage 1a (refusal imitation in an instruction format) does not apply directly. The movability
  test may transfer, since a memorized trigger → payload string should be "immovable" (untested).
- **Cost at scale** (our arithmetic): 3–4× training compute per screened update is unaffordable for every
  contribution. Screen a beacon-chosen sample and lean on reputation. It combines with OPEN-1B exact replay
  (2609.17380): replay proves a peer trained on its assigned tokens; behavioral screening catches poison that
  replay cannot judge, such as poison inside an approved shard.
- **Versus robust aggregation** (Soft Throttling 2609.39357, median-norm clipping): those bound update size
  and direction. A backdoor update can be small and well aligned. AlignIns, an alignment-based filter, missed
  up to 25% of attacker edges while rejecting over a third of honest adapters (Table 1).

## 6. Caveats

- Fine-tuning only: LoRA adapters of about 80 MB, 16 nodes, 24 rounds. Not pretraining, not full-parameter
  pseudo-gradients, not thousands of peers.
- One backdoor family: refusal targets (denial of service on triggered prompts). Payloads that are not
  refusals (malicious code, tool calls, false facts) would need other detectors; untested.
- An honest majority is assumed in every neighborhood. In a permissionless network, Sybil identities can
  break this unless verifier sets are drawn by a beacon with identity caps.
- The adaptive attacker targets only the probe stage, on one seed. No attacker optimizes against the
  movability test.
- Several results use one seed (Tables 6–9). The 2- and 3-attacker runs used a variant of Stage 1a and
  report replayed false-positive rates (footnote 2).
- The code is behind an anonymized link; long-term availability is unverified.
