# 2609.37899 — Scaling Zero-Order Pretraining through Model Sharding (SOMA)

## 1. Citation

- **Title:** Scaling Zero-Order Pretraining through Model Sharding
- **Authors:** Francois Chaubard, Mykel J. Kochenderfer, Chris Ré (Stanford University)
- **Date:** arXiv v1, 29 Sep 2026 (preprint)
- **arXiv:** 2609.37899 [cs.LG]. Code and checkpoints are said to be released.
- **Method name:** SOMA, Sharded Optimization Mixture of Assemblies.

## 2. Summary

Zeroth-order (ZO) estimators such as SPSA have relative gradient variance of about
`(d - 1)/n_pert` in the number of jointly perturbed parameters d. Big monolithic models therefore
learn slowly per unit of compute. SOMA changes the architecture instead of the estimator. The model
is an **ensemble of N small independent experts**, here byte-level 2-block LSTMs. Each expert:
- is trained on its own semantic data cluster (tf-idf, then SVD, then balanced k-means, as in
  Cluster-Branch-Train-Merge);
- uses **its own loss**, optimizer state and GPU;
- runs SPSA on only its `M/N` parameters, with no gradient, activation or state exchange.

A shared, tied embedding/decoder is learned once in a short seed run with an exact local
"delta-rule" decoder gradient, then frozen. At inference a fixed tf-idf router picks the top
`k = min(4, N)` experts from a 256-byte prefix and averages their next-byte probabilities.
On a separable objective, independent losses cut relative variance by about `1/N` versus a shared
loss, at equal aggregate forward compute. At about 8.44M parameters and 150 GPU-hours, SOMA N = 2
reaches 1.76 test nats/byte, against 2.00–2.11 for monolithic SPSA and 2.21 for EGGROLL. Backprop
(BPTT) is still about 2× better in loss at every budget tested.

## 3. Algorithm

### Symbols
- `N`: number of experts (shards). `e ∈ {1..N}`.
- `θ_e ∈ R^{d_e}`: expert e's perturbed body parameters (LSTM and MLP weights plus norm gains).
  `d_e = M/N` at fixed total size M.
- `E ∈ R^{V×d_E}`: shared tied embedding/decoder (V = 256 bytes, d_E = 32). Never perturbed.
- `L_e`: mean next-byte cross-entropy of expert e on a minibatch drawn from its own cluster `D_e`.
- `z_j`: probe vector. `ε`: perturbation radius. `n_pert`: probes per batch. `B`: sequences per batch.
- `A`: number of independently sampled accumulation batches per update.
- Adam: `β1 = 0.9`, `β2 = 0.999`, `δ_Adam = 1e-8`. `η_t` is the learning rate. `λ` is coupled weight decay.

### Recipe (Seed, Cluster, Branch, Train, Merge)
1. **Seed:** train one N = 1 model for 1,000 updates on a 10B-byte FineWeb-Edu subset
   (n_pert = B = 64, lr 0.0025). The body uses SPSA. The head E uses the decoder-path delta rule:
   ```
   ∇_E L_dec = (1/(B T)) Σ_{b,t} (p_{b,t} - onehot(y_{b,t+1})) h_{b,t}^T,   p = softmax(E h)   # eq (7)
   ```
   Hidden states are held fixed, with no backprop through the recurrence. This is the exact
   gradient through the decoder path only, ignoring the tied input use. (DUST's exact softmax head
   gradient is the same idea.)
2. **Cluster:** split the corpus into 1,024-byte windows. Word-level `TfidfVectorizer`
   (max_features = 50,000, sublinear TF, English stopwords, min_df = 5), then truncated SVD to 128
   dimensions, mean subtraction and L2 normalisation, then **balanced spherical k-means** with N
   centroids fit on 400k sample windows. Assign each window to its nearest centroid. Split each
   shard 99/1 into train and expert-validation.
3. **Branch:** copy the seed body (and E) into all N experts. In the width-32 ensembles E is frozen.
4. **Train (per expert, fully independent):** for each accumulation batch, sample n_pert sparse
   Rademacher probes. For ordinary weights each coordinate is 0 with p = 1/2 and ±1 with p = 1/4
   each, with **no** inverse-probability rescaling. Norm gains are always ±1. All probes and both
   signs share one batch.
   ```
   g_hat(θ) = (1/n_pert) Σ_j [L_B(θ + ε z_j, E) - L_B(θ - ε z_j, E)] / (2ε) * z_j      # eq (2)/(8)
   g_t      = average of g_hat over A accumulation batches (A · n_pert directions)
   g_t     += λ θ_t                                           # coupled weight decay, λ = 1e-4
   m_t = β1 m_{t-1} + (1-β1) g_t ;  v_t = β2 v_{t-1} + (1-β2) g_t^2
   θ_{t+1} = θ_t - η_t * (m_t/(1-β1^t)) / (sqrt(v_t/(1-β2^t)) + δ_Adam)
   ```
   Cost is 2·A·n_pert forwards per update. Vectorise with a leading perturbation axis:
   `(B,T,d) → (n_pert,B,T,d)`.
5. **Schedule:** initial `ε = lr = 1e-3` (main sweeps). Both halve together when expert-validation
   loss has not improved by 1e-8 for 1,000 updates, with a floor of 1e-5.
6. **Merge / inference:** route on the first 256 bytes with the same vectorizer, SVD and centroids,
   pick the top `k = min(4, N)` experts, then `p(y_t | x_<t) = (1/|S|) Σ_{e∈S} p_e(y_t | x_<t)`
   (eq 1). Hidden state is reset per window. Score bytes 257–1024.

### Architecture (expert body)
Each expert has D = 2 pre-norm residual blocks. Each block is a bias-free LSTM sublayer followed by
a GELU MLP (hidden size 4·d_t), with gain-only LayerNorm and a final norm.
`M_body = 16 D d_t^2 + (2D+1) d_t`, which is 32.9k parameters at d_t = 32. The shared head is
`V·d_E` = 8.19k. Fixed-size controls (Table 2): N = 1/2/8/256 use d_t = 509/361/181/32, giving
8.33M/4.20M/1.06M/32.9k per expert and about 8.4M total.

### Distributed regimes
- **FSO (Fully Sharded Optimization):** one expert per GPU with zero communication. Wall time per
  step does not grow with N.
- **DDPP (Distributed Data and Perturbation Parallelism):** one model's probes and batches are split
  across GPUs. Every global step a coordinator averages the local estimates and broadcasts the result.
  The monolithic baselines use this regime.

### Theory (Prop. 1, App. F)
With dense Rademacher probes and ε → 0:
- `E||g_hat - g||^2/||g||^2 = (d - 1)/n_pert + O(ε^2)`.
- Ratio of SOMA to monolithic variance: `(M/N - 1)/(M - 1) → 1/N`, at equal parameter-forward cost
  (`N · 2(M/N) = 2M`).
- The largest stable step size is `η ≤ 1/(L_sm (1 + (M/N - 1)/n_pert))`.
- With a shared batch: `v = a/n_pert + ν/B + aν/(n_pert B)`, where `a = d - 1` and `ν = σ_data^2/||g||^2`.
  At fixed `K = n_pert·B` the optimum is `B* = sqrt(K ν / a)`.

## 4. Key reported results

- **About 150 aggregate GPU-hours, about 8.44M parameters (Table 4), test nats/byte:**
  | config | n_pert | updates | GPU-h | test |
  |---|---|---|---|---|
  | **SOMA N = 2** | 64 | 65.0k | 150 | **1.76** |
  | Monolithic SPSA | 64 | 30.0k | 152 | 2.00 |
  | Monolithic SPSA | 256 | 1.32k | 150 | 2.11 |
  | Monolithic SPSA | 1024 | 839 | 148 | 2.00 |
  | Monolithic EGGROLL | (pop 220) | 7.40k | 141 | 2.21 |
  On WikiText-103 the same frozen checkpoints score 2.07, 2.25–2.36 and 2.49. SOMA N = 2 does
  2.2× more updates per GPU-hour than the 4-GPU DDPP monolith. At equal updates (30k) it scores
  1.87 vs 2.00.
- **Equal tuning, 3 seeds (Table 7):** SOMA N = 2 beats monolithic SPSA by 0.0396 ± 0.0057 nats/byte.
  Both select lr = 1.25e-3, the lowest value tried.
- **Independent vs summed loss (same N = 4 model, weights, data, probes; App. J):**
  - measured variance is 3.19–4.64× lower (4× predicted);
  - after 1,000 updates, test loss is −0.035 nats/byte in all 3 seeds and better on 4,090 of 4,096
    documents;
  - late in training (4M updates) the gain is tiny (0.0003).
- **Gradient error per GPU-second (Fig. 5):** going from n_pert 64 to 1024 cuts error by 94 %, and B
  64→1024 cuts it by 47 %. N = 256 is 99.5 % lower than N = 1 at fewer GPU-seconds per global step
  (118× lower centred variance).
- **Scaling N at fixed expert width:** validation loss falls from 1.84 to 1.72 (N = 1→256). The best
  endpoint is N = 8, n_pert = 1024 at 1.69.
- **Backprop is far ahead (Table 5):** at 50/100 GPU-h, N = 1 scores SOMA 2.12/2.03 vs BPTT
  1.02/1.01, and N = 2 scores 1.94/1.83 vs 1.07/1.05. "These SOMA recipes do not show a training
  advantage over backpropagation."
- Inference: N = 256 with top-4 runs at 2.36M tok/s vs 257k for N = 8 (9.19×), at about 60× the
  training compute.

## 5. Classification for Crowd v1.5

**Complement to DUST.** It is an architecture and training-topology decomposition. DUST (or SPSA)
remains the per-shard estimator. A radical variant, "each volunteer trains its own expert", is
effectively a replacement for the coordinator loop.

DUST shortcomings it addresses:
- **Low cosine / high variance:** the variance of each estimate scales with the *shard's* dimension,
  not the whole model's. The transferable lesson is **"independent losses remove cross-block
  perturbation noise."** In DUST terms: `mode="all"` perturbs every layer in one pass and scores
  every layer against one global loss change, so layer l's estimate carries noise from all the
  other layers. `mode="layer"` isolates them at L× the passes. SOMA's 1/N result predicts how much
  `"all"` loses. It also motivates a middle ground: perturb disjoint *groups* of layers per draw.
- **Communication and async/stragglers/heterogeneity:** FSO needs **zero** per-step communication.
  Each volunteer could own one expert and its cluster and be slow or fast without blocking anyone.
  Merging is inference-time routing.
- **Byzantine / untrusted peers:** damage is contained to one expert. A bad expert is visible on
  held-out data from its cluster and can be dropped or retrained before merge. No poisoned gradient
  enters a shared model.
- **Memory on consumer GPUs:** experts are small. The 1B-total question becomes "many 10–100M
  experts", each of which fits easily.
- The cost is that there is **no joint representation learning**. With N = 256, each expert sees
  1/N of the data (about 700 epochs over its shard). Inference becomes an ensemble, not one GPT.

## 6. MVP recipe (M5 Max, MPS, about 2–10 min)

Base: 10m preset GPT (`ModelConfig.preset("10m")`, `context_length=128`, about 7M parameters,
vocab 4096) on FineWeb-Edu tokens.

**Experiment A: the "independent losses" effect inside DUST (about 2 min, most relevant).**
1. Take a checkpoint after about 200 Adam steps and fix one batch. Compute the backprop reference
   (`backprop_gradients`).
2. At equal *total* perturbed forwards K ∈ {32, 128}, estimate all hidden-layer gradients three ways:
   - (a) `mode="all"`: every layer perturbed in each draw, one shared loss delta;
   - (b) `mode="layer"`: one layer per draw, K/L draws per layer;
   - (c) a group mode: G ∈ {2, 3} disjoint layer groups.
3. Plot relative error `Σ_l E||ĝ_l - g_l||^2 / Σ_l ||g_l||^2` (paper eq 5) against K.
   **Proves out if** the error ratio between modes tracks the dimension ratio predicted by
   `(d_group - 1)/(d_total - 1)` (for activation noise, d is the number of perturbed activation
   coordinates per token). That tells us which mode to ship.

**Experiment B: SOMA-lite vs monolith (about 8 min).**
1. **Cluster:** take about 20k FineWeb-Edu windows of 128 tokens. Features are the normalised
   token-count vector over 4096 ids, reduced to 64 dimensions with `torch.pca_lowrank`. Run
   spherical k-means with N = 4, simply balanced by capacity-capped assignment. Use sklearn's
   tf-idf instead if it is installed.
2. **Arms, matched on total forward FLOPs:**
   - (i) monolithic 7M GPT trained with DUST;
   - (ii) four 1.75M GPTs (d = 128, 6 layers, sharing a frozen embedding/head from a 100-step Adam
     seed run), each trained with DUST on its own cluster as 4 simulated workers run round-robin;
   - (iii) like (ii) but with the summed loss of all four (the paper's control);
   - (iv) Adam backprop on the monolith.
3. **Evaluation:** on held-out windows, route by nearest centroid of the first 32 tokens, average
   the top-2 expert probabilities, and score the remaining 96 tokens.
4. **Metrics:** loss vs aggregate forward FLOPs and vs simulated wall time. Wall time for (ii) is
   max-over-workers, since there is no communication. Also track bytes communicated (0 for (ii)).
5. **Proves out if** (ii) beats (i) at equal FLOPs and (ii) beats (iii) in every seed. Expect (iv)
   to dominate everything, as in the paper. Report the gap honestly.

Minimal pieces: a k-means router (about 30 lines), an ensemble-probability evaluator, and a loop
that trains N DUST models with independent optimizers. The existing `DustOptimizer` is reused.

## 7. Caveats / what is unclear

- **The ZO win is over other ZO methods only.** BPTT is about 2× better in nats/byte at every budget
  and model tested. The "win" depends on choosing a monolith baseline handicapped by DDPP
  communication.
- These are **byte-level LSTMs at about 8M parameters**, not transformers. The authors avoided
  transformers because of KV-cache memory at inference. There is no evidence for GPT experts or a
  4096-token vocabulary; they flag that the frozen byte decoder "does not establish feasibility of a
  larger token vocabulary".
- The sparse probes (density 0.5, no 1/q rescale) make the expected update `q_j g_j` rather than
  `g_j`, which interacts with weight decay (2× relative on ordinary weights). This is not justified
  beyond being recorded.
- The 1/N variance result needs a **separable objective**. A routed ensemble is not trained on the
  routed mixture loss, so the variance gain does not translate 1/N into loss. Late-training gains
  are tiny.
- Data per expert shrinks as 1/N. At N = 256 the shards are heavily reused (about 700 passes). For a
  crowd at 1B with many volunteers, data is not scarce, but expert *quality* is width-limited.
- Most scaling sweeps are single-seed. Compute accounting mixes recorded, W&B and fixed-rate
  conventions (Table 3). The EGGROLL comparison uses a different architecture (GRU) and untied head.
- For Crowd, merging independent experts gives up the "one shared model" story. It may be best used
  only for the *layer-group isolation* lesson (Experiment A), not the full ensemble.
