# 2609.39357 — Robustifying Asynchronous SGD via Soft Throttling (THROTTLE)

## 1. Citation

- **Title:** Robustifying Asynchronous SGD via Soft Throttling
- **Authors:** Kaoru Otsuka* (OIST), Maxime Meyer* (NUS; work done during an internship at OIST),
  Yuki Takezawa (Toyota), Makoto Yamada (OIST), Anastasia Koloskova (Univ. Zurich). *Equal contribution.
- **Date:** arXiv v1, 30 Sep 2026 (cs.LG), preprint
- **arXiv id:** 2609.39357

## 2. Summary

Asynchronous SGD applies each client's gradient as soon as it arrives. That removes straggler stalls, but it
lets fast or *flooding* clients dominate the model. A Byzantine client can submit unlimited updates.
THROTTLE splits training into **rounds**. Within a round, each client's first gradient gets step size η/n and
passes through a *local* robust aggregator, such as centered clipping around an anchor. Its c-th repeat (c≥1)
gets η/q^c and is norm-clipped. So any single client's total influence per round is bounded by
η(1/n + 1/(q−1)). A round ends once **every** client has delivered at least once. At that point the server
**hard-restarts**: it broadcasts the current model, discards all in-flight computation, and resets the counters.
q=1 is roughly plain async SGD and q→∞ is synchronous Byzantine-robust SGD. The paper proves a non-convex rate
that interpolates between the two and holds against flooding with no bound on the Byzantine update fraction.
Empirically, THROTTLE beats async SGD even without attackers (least squares, 40 Ray workers) and is robust on
MNIST under most attacks, though not under Empire.

## 3. Algorithm

### 3.1 Symbols
- `n`: number of clients. `G`, `B`: honest and Byzantine sets. `δ = |B|/n < 0.5`.
- `x(t)`: server model after t updates. `j_t`: client whose message is applied at t. `τ_t`: its delay. Its
  gradient was computed at `x(t−τ_t)`.
- `S_r`: start index of round r. `r(t)`: start of the current round. `c_i(t)`: number of gradients client i has
  already delivered in the current round.
- `q ∈ [1, ∞]`: throttle factor. Experiments use q ∈ {1.1, 1.5}.
- `η`: base step size. `λ_t`: clipping radius for repeat gradients.
- `A(v; S)`: local robust aggregator map with side information `S`. Averaged over one input per client, it
  equals a (c, δ)-robust aggregator: `Agg(x_1..x_n; S) = (1/n) Σ A(x_i; S)`.

### 3.2 Step-size rule (Eq. 2)
```
η_t = η / n          if c_{j_t}(t) = 0        (first arrival this round)
η_t = η / q^{c_{j_t}(t)}   otherwise          (2nd arrival: η/q, 3rd: η/q², ...)
```
The per-client total weight per round is at most `1/n + Σ_{i≥1} q^{-i} = 1/n + 1/(q−1)`. For q=1.1 that is
1/n + 10. For q=1.5 it is 1/n + 2.
Note that repeat weights (η/q, about 0.91η at q=1.1) are much *larger* than first-arrival weights (η/n).
The first arrivals jointly sum to a weight-1 robust average step. Repeats behave like near-full-step async SGD
updates that decay geometrically.

### 3.3 Server loop (Alg. 1)
```
send x(0) to all; c_i = 0 ∀i; side info S_0 (anchor a_0 = 0)
for t = 0..T-1:
    receive v from client j (computed at stale x(t−τ))
    if c_j == 0:  g = A(v; S_r)                 # local robust aggregator
    else:         g = clip_λ(v)                 # clip_λ(v) = v·min(1, λ/||v||)
    η_t = η/n if c_j == 0 else η / q**c_j
    x ← x − η_t · g
    c_j += 1
    send x to client j                          # client immediately starts next gradient
    if all c_i ≥ 1:                             # round ends
        S_{r+1} = t; update side info; c_i ← 0 ∀i
        broadcast x + RESTART to all; clients drop in-flight work and recompute at x
```
**Honest client:** wait for a model, sample ξ, compute ∇F(x; ξ), send it, repeat. On RESTART, discard the
current work and compute at the restart model.

### 3.4 Local robust aggregator used: centered clipping (Example 1)
- `A(v; a, τ_c) = a + clip_{τ_c}(v − a)`, with `clip_τ(u) = u·min(1, τ/||u||)`. Each first arrival can move the
  aggregate by at most τ_c/n.
- **Anchor:** `a_r = Π_G( (1/n) Σ_i g_i^{(S_{r−1})} )`, the mean of the previous round's first arrivals,
  projected onto the L2 ball of radius G. `a_0 = 0`.
- **Theory:** use `S = (a_r, 2G)` and `λ_t = G` (the gradient-norm bound). Then honest inputs are not changed.
- **Alternative (new):** Centered Truncated Mean, `ψ(u) = u·1{||u|| ≤ R}`, with `R² = V²/δ`. Error ≤ 10δV².
- **Impossibility (Prop. 2):** with no side information (no anchor), no per-input map `f` makes
  `(1/n)Σ f(x_i)` robust.

### 3.5 Theory (Thm 1, non-convex, L-smooth, ‖∇F‖ ≤ G, i.i.d. data)
`E||∇f(x_out)||² = O( (cδσ² + G²|B|²/(q−1)²)·θ_T + sqrt(Lσ²Δ/T_eff · (1−θ_T + θ_T/|G|))
 + (LΔ/T_eff)^{2/3} (1−θ_T)^{1/3} ((n−1)²G² + cδσ² + G²|B|²/(q−1)²)^{1/3} + LΔ/T_eff )`

- `T_eff = 1 + Σ_t η̂_t/η`: effective steps. `θ_T = N_T/T_eff`: restart ratio.
- `x_out` is sampled with probability proportional to η̂_t.
- η is chosen as a min of three terms, including 1/(4L).
- The **non-vanishing** error term `G²|B|²/(q−1)²` comes from asynchrony and persists even with full
  gradients. Momentum does not remove it; the paper leaves that open.

## 4. Key reported results

- **Least squares, no Byzantines (Table 2, tail-mean F−F\*, budget 32k gradients):**
  | Method | η | tail mean |
  |---|---|---|
  | Minibatch SGD (q=∞) | 0.198 | 3.46e-3 |
  | Async SGD (q=1) | 0.5 | 1.37e-4 |
  | THROTTLE q=1.1 | 1.587 | 7.14e-6 (±7.4e-6) |
  | THROTTLE q=1.5 | 3.175 | 2.55e-6 (±1.1e-6) |
  | Async µ²-SGD / BASGD / BASGDm | – | 1.8e-2 / 8.9e-3 / 7.0e-3 |

  THROTTLE tolerates a larger η than async SGD and ends about 20–50× lower. With one 100× straggler, the
  convergence per computed gradient barely changes.
- **MNIST under attack (Fig. 2/6):** THROTTLE keeps high accuracy under RD, NG, and ALIE, and under fixed and
  random flooding up to ρ=30 (94% Byzantine updates). BASGDm and µ²-SGD degrade under flooding.
  **Failure case: Empire.** THROTTLE gets 59.6% (q=1.1) and 61.5% (q=1.5), vs. 96.0% for BASGDm and 94.0% for
  µ²-SGD-RFA. The authors attribute this to missing momentum.
- **No-attack MNIST accuracy:** THROTTLE 99.2% (q=1.1, η=0.1 or 1), equal to µ²-SGD.

## 5. Classification for Crowd v1.5

**Complement to DUST.** It is a coordinator aggregation rule, not an estimator.

- **Byzantine / untrusted peers:** the main fit. It bounds per-client influence under flooding with no
  assumption on update rate. Centered clipping around a previous-round anchor is cheap. It is O(d) per upload
  and needs no forward passes, unlike LossScore.
- **Async / stragglers / heterogeneity:** fast consumer GPUs contribute more, but with geometric decay. Slow
  clients still get their 1/n robust slot every round.
- **High variance:** clipping repeat updates (λ) and the robust first-arrival average help with heavy-tailed
  DUST estimates. The theory needs ‖g‖ ≤ G, and ZO estimates violate this in practice, so clipping becomes
  essential.
- **Not addressed:** communication bytes, compute per useful step, memory.
- **Critical gap for thousands of peers:** a round ends only when **all n** clients have delivered. One dead or
  withholding client stalls round turnover forever. Its repeats keep decaying, so it does not stall progress,
  but anchors never refresh. Our version needs a round timeout or quorum, which the paper does not cover.
  Per-client throttling is also **Sybil-vulnerable**: k identities get k·(1/n + 1/(q−1)) influence. It
  therefore needs an identity or stake layer (as in Covenant/Gauntlet).

## 6. MVP recipe (M5 Max, MPS, PyTorch 2.15, about 2–10 min)

**Setup:** a 7M-parameter GPT (vocab 4096, seq 128, FineWeb-Edu). Use a single process with a **virtual-clock
event simulator**, following the paper's MNIST simulator. There are n=16–32 clients. Client i's compute time is
exponential with mean `μ_i ∝ 1/(i+1)`, or a {1,2,5,20}× speed mix. The server holds `x`. Each client stores the
model *snapshot* it was handed. To save memory at 7M parameters, store a version id and keep a ring buffer of
the last K model versions, and evict clients whose version is too old. The client computes its gradient on that
snapshot when its event fires.

**Gradient source per message (two variants):**
1. A backprop minibatch gradient. This is the faithful reproduction.
2. A DUST estimate at the stale snapshot. This is the integration test.

**Minimal pieces:**
- Counters `c[i]` and a round-membership set. On round end: anchor update, restart broadcast, and in-flight
  discard. Count discarded gradients against the budget, as the paper does.
- `A(v) = a + clip_{τc}(v − a)` for first arrivals and `clip_λ(v)` for repeats. Set `λ` ≈ median honest
  ‖g‖ and `τc` ≈ 2–3× median. These are our choices; the paper's MNIST values (λ=1, τ=100) are model-specific.
- Step `x -= η_t · g`. Use plain SGD for fidelity. Optionally add server momentum as an extra ablation; it is not
  in the paper.
- **Attackers** (5 of 20): NG (−10g), ALIE, and flooding (fixed random vector at 10× median norm, ρ ∈ {3, 30}).
- **Practical extension to test separately:** a round timeout. End the round when a fraction ≥ p of clients
  have arrived *or* a deadline passes.

**Arms:**
- q ∈ {1 (async), 1.1, 1.5, ∞ (sync, robust)}
- `adam` (centralized reference)
- `dust` (current coordinator: average + SGD with momentum)

Tune η on a 3-point grid per arm.

**Metrics:**
- val loss vs. computed gradients
- val loss vs. virtual wall time
- under attack: final loss ratio attacked/clean
- fraction of updates from the fastest 10% of clients vs. their share of total influence

**"Proves out" if:**
1. Without attackers, q=1.1 or 1.5 matches or beats async SGD at equal computed gradients and beats sync at
   equal wall time.
2. Under flooding with ρ=30, THROTTLE stays within a few percent of clean loss while plain async/averaging
   diverges.
3. The same ordering holds when gradients are DUST estimates. That would show the clipping and anchor survive
   ZO noise.

## 7. Caveats / unclear points

- **Internal inconsistencies:**
  - The MNIST client count is n=25 in the main text but n=20 (15+5) in App. E.
  - The text says q=1.1 had the lowest final gap, but Table 2 tail means favor q=1.5 (2.55e-6 vs. 7.14e-6).
- **Round termination needs every client.** That is unrealistic with churn, and there is no timeout or quorum.
- **Scale and tasks are tiny:** least squares (d=400) and a 66k-parameter MNIST CNN. No LLM or transformer
  results, no momentum or Adam, i.i.d. data only.
- **Theory gaps:** the analysis assumes bounded gradients and λ=G (so clipping is inactive). The experiments use
  λ=1, where clipping is active, which the theory does not cover. The asynchrony error term
  `G²|B|²/(q−1)²` does not vanish.
- Empire attack is a known failure (about 60% vs. 94–96%). Momentum, the suggested fix, is untested.
- Byzantine clients in the simulator are omniscient but rate-limited by ρ. Coordinated Sybils, and attacks on
  the anchor itself (poisoning the previous round's first arrivals within τ_c), are not studied.
- **Hard restarts discard in-flight work.** With slow consumer GPUs and long DUST evaluations, the discarded
  fraction could be large. The paper counts discarded work in the budget but does not report the fraction.
- The paper's AI-use statement says LLM coding agents implemented methods and pipelines. The baselines were
  reimplemented (BASGD, BASGDm) or ported. Treat baseline numbers with some caution.
