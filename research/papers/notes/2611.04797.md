# 2611.04797 — MobileSpec / FuRA-S: Forward-Only ES over Block-Spectral Coordinates

## 1. Citation
- **Title:** Training Specialist LLMs on Your Phone: Forward-Only Optimization via Block-Spectral Coordinates
- **Authors:** Liyan Tan*, Yequan Zhao*, Ziyue Liu, Yupeng Su, Ruijie Zhang, Zheng Zhang (UC Santa Barbara)
- **Date:** 3 Nov 2026 (v1), arXiv:2611.04797 [cs.LG]

## 2. Summary
MobileSpec trains small "specialist" adapters for an on-device INT4 LLM using forward passes only.
- **Core algorithm, FuRA-S:** split each weight matrix into K column blocks, factor each block exactly with an
  untruncated SVD (W_k = L_k diag(s_k) R_kᵀ), freeze L_k and R_k, and train **only the block singular values**
  s_k. That is about 0.015–0.05% of parameters (about n values per n-input matrix).
- **Optimizer:** antithetic evolution strategies (ES) with relative perturbations D = diag(µ_rel|θ0|) and
  population-standardised fitness. For likelihood objectives it can instead apply Adam to a MeZO two-point
  estimate.
- **Why this search space:** RLVR fine-tuning mostly *rotates* singular vectors and preserves singular values
  ("spectral inheritance"). Rescaling block singular values independently rotates the global singular frames
  about 4× more than a dense update of equal norm, while barely changing the spectrum. ES therefore keeps
  finding improving perturbations for longer: 8.3% of members beat the center at iteration 100, vs 1.0% for
  full-parameter ES and 0% for LoRA.
- **Exact rewrite for INT4:** W′ = W(I + R diag(δ) Rᵀ), so the update is an input transform in front of the
  frozen INT4 kernel.

Results:
- Matches full-parameter ES on Countdown and MATH RLVR.
- Beats LoRA-ES, VeRA-ES, and quantized ES (QES) by up to 16 points.
- Phone-use agents go from 6–23% to 89–100% success.
- Trains a personalized 8B model on an iPhone 16 Pro overnight.

All of this is **post-training/fine-tuning** of pretrained models.

## 3. Algorithm

### Notation
- **Shapes:** W ∈ R^{m×n} (m outputs, n inputs). K column blocks of width b, with n = K·b. The paper picks the
  factor pair of n closest to √n, with K ≤ b. Attention output projections are split by head. If m < b, the
  reduced SVD has m values per block.
- **Block SVD:** W_k = L_k diag(s_k) R_kᵀ, with L_k ∈ R^{m×b} (orthonormal columns), R_k ∈ R^{b×b}
  (orthogonal), s_k ∈ R^b. R = blockdiag(R_1..R_K) ∈ R^{n×n}.
- **Trainable state:** θ ∈ R^d is the concatenation of all s_k over all adapted matrices, initialised to the
  pretrained values θ0.
- **Relative parametrisation:** s′_k = s_k ⊙ (1+δ_k), with δ ∈ R^n per matrix.
- **ES quantities:** N is the population size, i.e. N/2 antithetic pairs. z_j ~ N(0, I_d).
  D = diag(µ_rel·|θ0|). α is the step size. F is fitness (reward, or negative loss / mean log-likelihood).

### Forward with adapted weights (exact, Eq. 4–5)
W′ = [L_1 diag(s′_1) R_1ᵀ | … | L_K diag(s′_K) R_Kᵀ] = W (I + R diag(δ) Rᵀ),
so **y = W (x + R diag(δ) Rᵀ x)**.
- This needs only per-block b×b matmuls: cost 2·n·b MACs per token per matrix, i.e. about b/m of the dense cost.
- δ = 0 recovers the base model exactly. L_k never has to be stored if you keep W.
- Total extra storage is K·b² = n·b values per matrix (about 3%), which is the R_k.

### FuRA-S ES loop (Alg. 1, Eq. 3)
```
for each adapted W: block-SVD → (L_k, s_k, R_k);  freeze L_k, R_k
θ0 = concat(s_k);  D = diag(µ_rel · |θ0|)
for t = 0..T-1:
    for j = 1..N/2:
        z_j ~ N(0, I_d)                   # regenerated from seed, never stored
        f+_j = F(θ_t + D z_j);  f-_j = F(θ_t − D z_j)
    standardize all N fitness values: f~ = (f − mean)/std     # over the whole population
    θ_{t+1} = θ_t + (α/N) · D · Σ_j (f~+_j − f~-_j) z_j
```
- There is no momentum. α absorbs 1/µ. Common random numbers: all members are scored on the same
  problems/batch within an iteration.

### FuRA-S with ZO-Adam (supervised / likelihood fitness, App. E, Eq. 16)
- Two-point estimate over P antithetic pairs, each pair on its own mini-batch B_j:
  ĝ_t = (1/P) Σ_j [L(θ_t + D z_j; B_j) − L(θ_t − D z_j; B_j)]/2 · z_j  (in normalised z-coordinates).
- Then θ ← θ − η · D · Adam(ĝ_t). In words: "applies Adam … before scaling the update by D".

### Hyperparameters (Table A2, App. C/E)
- **All reward ES:** µ_rel = 3e-2, α = 1, with standardised fitness.
  - Countdown: 15 pairs (30 members), 200 problems per member, 500 iterations.
  - MATH: 15 pairs, 1,024 prompts per iteration, 200 iterations.
  - INT4 Countdown: 25 pairs, 300 iterations.
  - Sudoku: 16 pairs, 100 iterations.
  - LaMP user-based: 15 pairs, 128 examples, 200 iterations.
  - LaMP per-user: α = 3, up to 64 examples, up to 20 iterations, early stop after 3 non-improving iterations.
  - Phone agent: 8 pairs (N=16), 4 greedy episodes per member, 15 iterations.
- **SFT** (Llama-3-8B, Commonsense-170K): ZO-Adam with µ_rel = 1e-2, peak LR 0.5, β=(0.9, 0.999),
  eps 1e-8, 3% linear warm-up then linear decay to 0. 8 pairs per update, 5,987 updates, batch 16. Same
  forward budget as first-order: 95,796 forwards = 3 epochs of BP counted at 3 forwards per BP step.
- **Full-param ES baseline** (ES at Scale): 30 independent perturbations, σ = 1e-3, α = 5e-4.
- **LoRA-ES:** rank 4, with perturbation magnitude matched per matrix.
- **Trainable counts:** Qwen2.5-0.5B 245,760; 1.5B 508,928; 3B 838,656; 7B 1,132,544. MAI-UI-2B 516,096.
  Llama-3-8B 1.25M (4.98 MB FP32).
- **Precision:** FP32 master θ. L_k in FP32/BF16 (NF4 optional). Perturbed weights evaluated in BF16.
  For INT4, R is stored in 4 bits.

### Step-wise fitness for long-horizon agents (Eq. 6, GiGPO-style)
- Return of step t in an episode of H steps: γ^{H−1−t} × episode reward, with γ = 0.95.
- Group steps across *all* members by screenshot dHash (Hamming distance ≤ 10).
- Advantage = Q̂(g, a) − V̂(g). Groups visited by fewer than 2 episodes get zero advantage.
- F_i = (1/J) Σ_episodes Σ_steps advantage.

## 4. Key results
- **Countdown accuracy** (Table 1; Full ES vs FuRA-S):
  0.5B 14.4 vs 14.4; Llama-1B 15.6 vs 15.8; 1.5B 36.7 vs 37.0; 3B 58.2 vs 55.8; 7B 58.9 vs 56.2.
  LoRA-ES is lower on every model (e.g. 1.5B: 34.7); VeRA-ES at 1.5B is 28.1. FuRA-S beats the BP-based
  PPO/GRPO/Dr.GRPO on 4 of 5 models.
- **MATH, Qwen2.5-Math-7B** (Table 2), Avg-5 / Avg-3: Full ES 45.2 / 47.2, LoRA-ES 40.4 / 44.1,
  FuRA-S 44.2 / 47.8. FuRA-S here also trains 131k LM-head offsets.
- **INT4 (GPTQ) Countdown at 300 iterations:** FuRA-S 21.85% / 50.40% vs QES 16.00% / 34.15% (1.5B / 3B).
  FuRA-S passes QES's best within 50 iterations.
- **Search-space diagnostic** (Fig. 5), share of members beating the center:
  - at base: Full 70.8%, LoRA 55.2%, U/V-only 74.0%, S-only 64.6%.
  - at iteration 100: Full 1.0%, LoRA 0%, U/V 8.3%, S 4.2%.
- **Ablations** (3B Countdown, 200 iterations): FuRA-S 49.25%. Whole-matrix SVD (SVF) 45.40%.
  Rademacher instead of Gaussian 39.60%.
- **SFT Commonsense-170K** (equal forward budget): FuRA-S 64.64% avg vs VeRA 61.66, MeZO 54.71,
  Sparse-MeZO 56.26, GRZO 68.70 (full parameter). With 4-bit L: 59.97 vs QuZO 43.00.
- **Phone agent** (Table 3), success % base → episode-reward → step-wise:
  MastodonReply 23 → 80 → 89; CheckEventTime 9 → 92 → 100; RequestCarpooling 6 → 14 → 98.
- **Costs:**
  - Training adds about 20 MB beyond the forward pass.
  - Llama-3-8B: 17.17 GB vs 16.26 GB for MeZO; 0.341 s per 16-example evaluation.
  - INT4 serving: +9% memory, +11–15% decode latency.
  - iPhone: 20 iterations take 10.4 h; val loss 0.85 → 0.19; 2.1 GB resident.

## 5. Classification for Crowd v1.5
**Complement to DUST, not a replacement.** It is useful for a post-pretraining or specialisation phase, and as
a source of design ideas. It is not a pretraining method.
- The whole argument rests on pretrained spectra: RLVR preserves singular values and rotates frames. At random
  init, block singular values of noise matrices are not a meaningful search space and cannot build features.
  Expect it to fail from scratch; that is worth one sanity run.
- DUST shortcomings it speaks to:
  - **Communication bytes.** The update is fully determined by seeds plus N standardised fitness scalars.
    Clients could upload only (seed, f+, f−) per pair, a few bytes. The trainable state is about 0.03% of
    params, so even dense deltas are tiny.
  - **Instability with relative σ.** It also uses relative perturbations (µ_rel|θ0|), but on singular values,
    which are positive and well scaled. Fitness z-scoring plus antithetic pairs bounds the step size regardless
    of the loss scale. This is a template for DUST's scoring: standardise the ΔL scores per population.
  - **Byzantine/untrusted peers, partly.** Standardised fitness bounds each member's influence. Seed-determined
    perturbations allow the coordinator to re-evaluate any member (our inference; not claimed in the paper).
  - **Memory on consumer GPUs:** forward only, about 20 MB of state, and INT4 base weights stay intact.
- It does not address gradient cosine in the pretraining regime, nor async training or stragglers.

## 6. MVP recipe (M5 Max, MPS, about 2–10 min)
Setup: a 7M GPT (vocab 4096, seq 128, d=256) on FineWeb-Edu, FP32.

1. **Pretrain base, about 2–3 min:** Adam backprop to a moderate loss (e.g. 3k steps). Save the checkpoint.
   This plays the role of the "pretrained generalist".
2. **Block-SVD reparametrisation:** for each nn.Linear (n=256 gives K=16, b=16; n=1024 gives K=32, b=32), use
   torch.linalg.svd per block. Keep W frozen, and precompute R (blockdiag) and θ0 = s. Write a forward wrapper:
   y = W(x + R diag(δ) Rᵀ x), with δ = θ/θ0 − 1 implemented as reshape(…, K, b) and two batched einsums.
   Check that δ = 0 reproduces the logits exactly.
3. **Continue training from the checkpoint** for an equal forward-pass budget (e.g. 20k forwards):
   - (a) Adam backprop (reference).
   - (b) DUST-like baseline on all params.
   - (c) Full-parameter antithetic ES / MeZO.
   - (d) **FuRA-S ES:** 15 pairs, µ_rel = 3e-2, α = 1, fitness = −mean CE on a shared batch of 32×128 tokens,
     standardised.
   - (e) **FuRA-S ZO-Adam** (Eq. 16): 8 pairs on separate batches, µ_rel = 1e-2, LR 0.5 with warmup/decay.
   - (f) **SVF control:** K = 1 (global SVD), i.e. no frame rotation.
   - (g) LoRA-ES rank 4 with matched perturbation norm.
4. Optionally simulate 8 workers. Each evaluates a few pairs on its own batch and uploads only
   (seed, f+, f−). The coordinator standardises and updates. Report upload bytes per step.
5. **Domain-shift variant**, closer to the paper's regime: pretrain on one FineWeb-Edu slice, then specialise
   on a distinct domain (e.g. code or a single topic). Measure the held-out domain loss.
6. **Metrics:** val loss vs forward passes and vs wall time; fraction of members beating the center over
   iterations (Fig. 5 diagnostic); ρ_Σ and frame rotation of the learned ΔW.
7. **From-scratch sanity run:** FuRA-S on a random init. We expect it to stall near the unigram loss.

**Proves out if:** in the continued-training or domain-shift setting, (d) or (e) beats (b) and (c) at an equal
forward budget, (f) is clearly worse than (d), the improving-member fraction stays above 0 longer than for (c),
and upload is under 1 KB per worker-step. For Crowd, it is only interesting as a post-training mode unless the
from-scratch run surprises us.

## 7. Caveats / unclear points
- Fine-tuning and RLVR only. "Spectral inheritance" is borrowed from other papers (ISO, "The path not taken");
  no pretraining evidence.
- MATH results use extra trainable LM-head offsets (H′ = H + C V over 2,048 answer tokens × 64 hidden-state
  eigendirections), so it is not pure block-spectral.
- Gaussian beats Rademacher by about 10 points, which the paper leaves unexplained ("properties beyond these
  two moments").
- Hyperparameters were tuned on Qwen2.5-1.5B and reused elsewhere. Most comparisons are single-seed (seed 42);
  the Qwen2.5-1.5B LoRA-ES comparison uses 2 seeds.
- Full-ES and FuRA-S differ in more than the search space: 30 independent vs 15 antithetic pairs,
  σ = 1e-3 absolute vs µ_rel = 3e-2 relative, and standardised fitness.
- The Countdown fitness uses a fixed 200 training problems evaluated every iteration, which is effectively
  full-batch with no minibatch noise.
- The block-partition rule is "factor pair of n closest to √n". Sensitivity to b is not reported beyond the
  K = 1 ablation.
- The Eq. 16 ZO-Adam scaling is described only in prose ("applies Adam … before scaling the update by D"),
  and whether ĝ divides by µ is implicit.
- Phone-agent results rest on 64 evaluation episodes per task. Training uses greedy decoding, with diversity
  coming only from emulator timing.
