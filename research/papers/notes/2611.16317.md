# 2611.16317 — WIS-MeZO: Wanda-Guided Sparse Perturbations for ZO Optimization

## 1. Citation
- **Title:** Wanda-Guided Sparse Perturbations for Efficient Zeroth-Order Optimization
- **Authors:** Ziqing Wen, Xiaohui Song, Jiahuan Wang, Ping Luo, Junlin Zeng, Dongsheng Li, Tao Sun
  (National University of Defense Technology; OPPO AI Center)
- **Date:** 12 Nov 2026 (v1), arXiv:2611.16317 [cs.LG]

## 2. Summary
MeZO (two-point SPSA with seed replay) has variance that grows with the number of perturbed coordinates.
Sparse-ZO methods perturb only a subset, and the question is which one. WIS-MeZO picks the subset with the
**Wanda pruning saliency** S_ij = |W_ij|·‖X_j‖₂, where X is the calibration activations of the layer input
from 128 downstream examples. In each row it keeps the top-k = ⌊r·n⌋ coordinates as a binary mask M. Only
masked coordinates are perturbed and updated; the model stays dense. The mask is computed once (WIS-MeZO) or
refreshed every τ steps (WISD-MeZO). The theory links Wanda scores to expected gradient energy, giving an
energy capture ratio ρ. The alignment of the masked estimator is √(ρ/(s+2)), vs √(r/(s+2)) for a random mask.
At r=0.05 on LLaMA-3.2-3B, the Wanda mask captures over 40% of gradient energy, vs 5% for a random mask. This
is a **fine-tuning** paper (3B–32B, GLUE/SuperGLUE/commonsense); it does not cover pretraining.

## 3. Algorithm

### Notation
- Linear layer W ∈ R^{m×n} (m outputs, n inputs). Mini-batch B. Loss f(W, B).
- Mask M ∈ {0,1}^{m×n}. Density r = k/n with k selected coordinates per row.
  d = Σ_ℓ m_ℓ n_ℓ (total), s = d_eff = Σ_ℓ m_ℓ k_ℓ = r·d (selected).
- Z has iid N(0,1) entries and is regenerated from a seed. ϵ is the perturbation radius; η_t is the learning rate.
- Calibration activations X ∈ R^{n×B_cal} for the layer input (columns = tokens/examples).

### Mask (Alg. 3, ComputeMask)
```
q_j  = ‖X_{j,:}‖₂                    # per input feature, over calibration tokens
S_ij = |W_ij| · q_j                   # Wanda score
k    = floor(n · r)
for each row i: M_i,: = 1 on TopK_j(S_i,:, k), else 0     # row-wise: equal budget per output unit
```
The mask uses 128 downstream calibration examples (32–512 tested; it plateaus at 128). Building it takes
0.5–1.3 s on a 3B model. It can be bit-packed at 1 bit per parameter.

### Perturbation direction
U = (Z ⊙ M)/√r, so E‖U‖_F² = m·n (the same expected energy as dense MeZO, concentrated on m·k coordinates).

### Update (Alg. 1, WIS-MeZO)
```
for t = 0..T-1:
    if t mod τ == 0: M = ComputeMask(W_t, X ~ D_cal, r)          # WIS: once; WISD: every τ
    sample batch B, seed s
    W += (ϵ/√r) Z⊙M          (Z regenerated from s)
    L+ = f(W, B)
    W -= 2(ϵ/√r) Z⊙M
    L- = f(W, B)
    W += (ϵ/√r) Z⊙M          # restore
    regenerate Z from s
    Ĝ_t = (L+ − L−)/(2ϵ) · (Z⊙M)/√r
    W  -= η_t Ĝ_t
```
- One direction per step and two forwards on the same batch, with constant LR and no weight decay. This is
  plain ZO-SGD with no momentum.
- **Seed replay:** the update is fully determined by (seed, scalar (L+−L−), mask), so no gradient tensor is
  stored.

### Theory (for intuition and diagnostics)
- **Energy capture:** ρ = E‖M⊙G‖_F² / E‖G‖_F². A random row-wise mask gives E[ρ] = r.
- **Lemma 5.3 / Thm 5.4:** under bounded input–error dependence (γ, ν) and calibration concentration
  (B_cal = Ω(K² log n/ξ²)), ρ_WIS ≥ κ_ξ ρ*, where ρ* is the row-wise oracle top-k energy. WIS beats a random
  mask if κ_ξ ρ* > r.
- **Lemma 5.5:** Align(Ĝ₀, G) = E⟨Ĝ₀,G⟩/√(E‖Ĝ₀‖²·E‖G‖²) = √(ρ/(s+2)). Ratio vs random mask: √(ρ/r),
  which is about 2.8× at r=0.05 with ρ=0.4.
- **Thm 5.8 (nonconvex, L-smooth, fixed mask):** with η_t = r/(4L a √(t+1)) and a = s+2,
  (1/T) Σ E‖∇f‖² ≤ [8La Δf + ½σ_ϵ²(1+log T)]/(ρ_min √T) + 4L²ϵ²s/(r ρ_min),
  where σ_ϵ² = σ² + L²ϵ² s(s+4)/(4r). The rate depends on s rather than d, and on captured energy ρ_min.
- A PL-condition version gives linear convergence to a neighbourhood.

### Hyperparameters (App. B, Tables 11–13)
- ZO runs: batch 16, 20,000 steps, sequence length 2048, constant LR, weight decay 0.
  FT/LoRA: batch 8 with AdamW.
- WIS-MeZO grid: LR ∈ {5e-8, 1e-7, 2.5e-7, 5e-7}, ϵ ∈ {1e-3, 1e-4}, r ∈ {0.05, 0.1, 0.2, 0.4};
  WISD τ ∈ {2000, 5000, 10000}.
- Typical selected values: LR 1e-7 to 5e-7, with r=0.1–0.2 most often (0.05–0.4 all appear).
  r=0.1 was best on 4 of 5 commonsense tasks.
- Baselines: MeZO LR 5e-8–5e-7. Sparse-MeZO (small-magnitude mask) needs about 10× larger LR (1e-6 to 5e-6).
  Random-MeZO uses the same LR range as MeZO.
- Results average 5 seeds on GLUE/SQuAD and a single run on SuperGLUE.

## 4. Key results
- **GLUE + SQuAD average** (Table 1). LLaMA-3.2-3B: MeZO 74.4, Random-MeZO 76.4, Sparse-MeZO 77.7,
  **WIS 79.1, WISD 79.8**, vs FT 86.5 and LoRA 86.6. Qwen2.5-3B: MeZO 85.4, WIS 86.9, WISD 87.0, FT 87.5.
  MNLI on LLaMA: 49.4 (MeZO), 61.2 (WIS).
- **SuperGLUE average** (Table 2). LLaMA: MeZO 72.8, Sparse 74.5, **WIS 77.3**, WISD 77.6, FT 79.4.
  Qwen: MeZO 80.1, WIS 81.7, WISD 82.9.
- **Scaling, Qwen2.5 commonsense 5-task average** (Table 3), MeZO → WIS:
  3B 65.1 → 68.8; 7B 66.9 → 70.0; 14B 71.8 → 75.1; 32B 72.3 → 75.4.
- **Steps to loss** (Fig. 1): on RTE, BoolQ, and MNLI, WIS reaches comparable validation loss in fewer steps than
  MeZO. Reading the plots, the gain is visible but modest.
- **Energy capture** (Fig. 2, r=0.05, 2000 AdamW gradient snapshots, masks fixed at step 0): WIS > 0.4;
  random ≈ 0.05; small-magnitude > random; large-magnitude < random. The advantage is largest at low r.
- **Cost** (Tables 4–6, Qwen2.5-3B): wall time is 2.1–10.7% above MeZO. Memory is 11.6 vs 9.7 GB on SST-2.
  At 32B, the 1-bit mask adds under 3 GB over MeZO.

## 5. Classification for Crowd v1.5
**Complement to DUST**, mainly for **communication bytes** and secondarily for **variance / low cosine**.
- WIS-MeZO is weight-space SPSA. DUST is activation-space, and NP variance already scales with the activation
  dimension, so masking weight coordinates does not reduce DUST's probe variance the way it reduces MeZO's.
- The transferable pieces are:
  1. **Saliency-chosen sparse support for uploads.** Clients could send only the top-r Wanda-salient coordinates
     of their per-layer estimate. The mask depends on W and a public calibration batch, so the coordinator and
     every client can compute it identically and indices never need transmitting. Upload ≈ r × dense.
  2. A cheap diagnostic, energy capture ρ, for choosing *any* sparsification mask (Wanda vs magnitude vs random).
  3. A "seed + scalar" upload mode if we ever run a MeZO-style weight probe. A masked probe still needs only
     (seed, ΔL) per probe, which is about 8 bytes. That is a huge byte saving, and the coordinator can verify a
     probe by recomputing it. This verification is our inference, not a claim in the paper; it is relevant to
     untrusted peers.
- **Caveat for pretraining:** Wanda saliency is motivated by *pretrained* weights. At random init, |W_ij| is
  noise and the score reduces to activation norm ‖X_j‖, i.e. "perturb high-energy input features". That is the
  same intuition as SZO-κ's C-shaping (2611.08712), applied as a hard mask. Expect a smaller gain from scratch;
  WISD-style periodic refresh is needed while weights change fast.

## 6. MVP recipe (M5 Max, MPS, about 2–10 min)
Setup: a 7M GPT (vocab 4096, seq 128) on real FineWeb-Edu tokens, FP32.

1. **Energy-capture diagnostic, about 2 min.** Train with Adam backprop for about 1–2 min and save 4–5
   checkpoints including init. At each checkpoint, compute the backprop G per Linear on 20 fresh batches and
   ρ(M) = ‖M⊙G‖²/‖G‖² for four masks at r ∈ {0.05, 0.1, 0.2}: Wanda (128 calibration sequences), random,
   small-|W|, and large-|W|. Also score the mask computed at checkpoint c against gradients at c+1, which is
   staleness relevant to WIS vs WISD.
   *Proves out if* ρ_Wanda ≫ r (e.g. ≥ 3r) after a short warm-up and stays high for the next checkpoints.
2. **Sparse-upload test with DUST, about 3–5 min.** Run DUST-like training with 4–8 simulated workers. Each
   worker computes its DUST per-layer estimate, keeps only the coordinates in the shared Wanda mask (scaled by
   1/√r or unscaled; try both), and the coordinator averages and applies SGD+momentum. Compare against the
   dense DUST upload, random-mask upload at the same r, top-k-by-|estimate| upload (which needs index
   transmission), and Adam backprop. Log val loss vs tokens, vs upload bytes, and vs wall time. Refresh the mask
   every τ ∈ {50, 200} steps.
   *Proves out if* Wanda-masked DUST at r=0.1 matches dense DUST loss within noise at 10× fewer upload bytes
   and beats the random mask.
3. **Optional, faithful MeZO comparison, about 3 min:** from an Adam-warmed checkpoint (e.g. 500 steps), run
   MeZO vs Random-MeZO vs WIS-MeZO (r=0.1, ϵ=1e-3, LR grid around 1e-5 to 1e-3 scaled for the 7M model,
   2000–5000 steps). Use seed replay and two-point probes on the same batch. Plot loss vs forward passes.
   *Proves out if* WIS-MeZO reaches MeZO's final loss in clearly fewer steps.

Minimal code: a Wanda mask function (hooks to collect ‖X_j‖ per Linear input), a seeded masked perturbation
(torch.Generator per step, regenerate Z), a masked aggregator in the simulated coordinator, and an
energy-capture metric.

## 7. Caveats / unclear points
- Fine-tuning only. Zero-shot starts are already strong; whether it helps **pretraining** from random init is
  untested.
- Energy capture was measured on gradients from an auxiliary **AdamW** run, not along the ZO trajectory itself.
- Alg. 1 line 14 writes Ĝ = (L+ − L−)/(2ϵ√r) · Z⊙M, which is consistent with U = Z⊙M/√r; the 1/√r factors in
  perturbation and update must match. The theory's LR η_t = r/(4La√(t+1)) differs from the constant LR used in
  experiments.
- SuperGLUE results are single runs, and many per-task gains are within one sd. The aggregates are consistent.
- Per-task tuned LR, ϵ, and r, from a grid larger than MeZO's (r adds a dimension), may contribute part of the gain.
- Row-wise top-k gives each output unit the same budget; other allocations (global top-k) are not compared.
- The constants in Thm 5.4 (γ, ν, w_min/w_max) can be loose; κ_ξ may be small when weight magnitudes vary a
  lot within a row.
- Memory overhead of an unpacked mask is significant (+25 GB at 32B), so bit-packing is needed.
- No distributed, communication, or robustness experiments; the upload-sparsity use above is our extrapolation.
