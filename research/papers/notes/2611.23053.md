## 2. Summary
Gossip training replaces the global all-reduce with exchanges among a few peers. That removes the central server
and the global barrier, but sending a full model to every peer is expensive. Compressed gossip (CHOCO-SGD) also
needs a fixed graph, because its messages are deltas against a reconstruction state the receiver must keep.
SPICE sends **absolute parameter values** for a sparse set of coordinates. Each replica picks the coordinates with
chunked Top-k from an error-feedback (EF) accumulator, and "corrects" the sent values so the EF memory is folded
in. Any receiver can read such a message without history, so peers can change every round. Each round, peers come
from a shared random permutation. The receiver averages each coordinate over itself and the peers that sent it,
and treats (own value − average) as a pseudo-gradient for an outer Nesterov optimizer (GASLoC's consensus
acceleration). At equal bytes, more peers with sparser messages beat fewer peers with denser ones. Growing the
peer count with the replica count nearly removes the usual loss degradation from 8 to 128 replicas at 134M.

## 3. Method
Algorithm 1 and Sec. 3.1–3.2. Per round t, replica i:
1. Inner step: `y_i = AdamW(x_i)`, local displacement `Δ_i = x_i − y_i`.
2. EF accumulator: `ẽ_i = β·e_i + Δ_i`, with EF decay β = 0.95.
3. Chunked Top-k on `ẽ_i`: chunks of b = 4096 coordinates, keep k = 128 per chunk, so density δ = k/b = 3.125%
   (Table 2). Residual `e_i ← (1 − M_i) ⊙ ẽ_i`.
4. Corrected endpoint: `z_i = y_i − M_i ⊙ β e_i`. On a selected coordinate this equals `x_i − ẽ_i` (Eq. 7).
5. Peers: every replica builds the same random permutation from a shared seed and the round index. It exchanges
   with the q/2 replicas before it and the q/2 after it on that cycle (App. B.1). No scheduling messages.
6. Message = (12-bit packed indices, values in the parameter dtype). Bytes sent per round =
   `q·δ·d_loc·(v + 1.5)`, where v is bytes per value (Eq. 12).
7. Per-coordinate average over {self} ∪ {peers that sent c}: `G_i[c] = x_i[c] − mean(z_j[c])` (Eq. 10). If
   nobody sent c, the replica keeps its own update.
8. Outer step: `x_i ← Nesterov(x_i, G_i)`. With full density (k = b), SPICE is exactly dense GASLoC.
- **Windowed variant** (Sec. 4.4.2): receive in the background. At a deadline (2× the healthy 99th-percentile
  exchange time), aggregate only complete peer messages; if none arrived, use the replica's own endpoint.
- **Hyperparameters** (App. B.5, Table 7): inner learning rate (LR) 2e-3 to 4e-3 (134M), outer LR 0.8–0.9,
  outer Nesterov momentum 0.1–0.3 (low). AdamW β2 scaled with replica count R as in 2610.19064:
  0.95/0.975/0.987/0.994/0.997 for R = 8/16/32/64/128. Global batch fixed at 1024 × 2048 tokens and split
  across replicas (Sec. 4.1). **Every decentralized method communicates after every local step (H = 1)** in
  the reported experiments (Sec. 4.1).

## 4. Key reported results
- **134M, 2.70B tokens, validation loss (Table 2a).** Distributed data parallel (DDP) reference 3.17.
  SPICE (q = R/2, δ = 3.125%) 3.19/3.19/3.20/3.21/3.23 for R = 8/16/32/64/128, +1.3% from 8 to 128.
  Dense 2-peer GASLoC 3.19 → 3.37 (+5.6%); SparseLoCo (H = 1, no quantization or outer momentum)
  3.27 → 3.42; CHOCO-SGD 3.27 → 3.86.
- **The flat curve needs q to grow with R.** At fixed q = 4 (0.12 model-sizes per round), loss goes 3.19 → 3.52
  from R = 8 → 128, +10.3% (Table 4, App. A.1). At R = 128, q = 64 sends 2d values per round, the same volume as
  dense 2-peer GASLoC (Table 4).
- **Peer batch (Fig. 7):** with qB/R (contacted peers × local batch) held fixed, loss stays roughly flat across
  R; a larger peer batch gives a lower loss.
- **551M, 11.01B tokens (Table 2b):** DDP 2.63; SPICE 2.65/2.68/2.70 (R = 8/16/32); 2-peer GASLoC 2.64/2.68/2.73.
- **OLMoE-1B-7B mixture-of-experts (MoE), 26B tokens, 8 replicas (Table 3):** SPICE (q = 4, δ = 6.25%) sends
  0.25d per round and reaches loss 2.368, vs 2.367 for 2-peer GASLoC (2d) and 2.362 for DDP. HellaSwag:
  52.38 ± 0.50 vs 52.71 ± 0.49 for DDP.
- **Fixed byte budget (Fig. 3b):** with 16 peers, SPICE beats both dense GASLoC baselines while sending less than
  half a dense model per round.
- **Wall-clock (Table 6; 8× RTX A6000 in one box, per-replica caps via Linux traffic control, no added latency):**
  551M at 1 Gbit/s: DDP 69:38 h, GASLoC q = 1 57:04, SPICE (q = 2, δ = 3.125%) 22:19, about 3.1× faster than DDP
  (our arithmetic). 134M at 1 Gbit/s: DDP 7:08 vs SPICE (q = 4) 1:55. SPICE throughput is almost flat from 10 to
  1 Gbit/s (Fig. 4). Time-matched, it has 6% lower validation loss than DDP at 1 Gbit/s (Fig. 5).
- **Slow links between "islands" (Fig. 6):** at 500 Mbit/s DDP (with TorchFT recovery) loses more than 2/3 of
  its throughput while SPICE keeps most of its own. At 100 Mbit/s DDP commits few updates and SPICE keeps about
  2/3. Windowed SPICE keeps about 86%, using 2.48 ± 0.88 of 4 peers per committed update.
- One seed per configuration (App. B.4).

## 5. Relevance to Crowd
- **Aggregation without a hub at large scale.** Each replica talks only to q peers. Partners are a deterministic
  function of (seed, round), so no tracker schedules exchanges, and a newcomer can join without history. Hub
  designs (Covenant's object store plus validator, Decoupled DiLoCo's syncer 2604.21428) carry every upload and
  every trust decision through one point. At 10^5–10^6 peers that becomes a bandwidth and trust bottleneck. SPICE
  is the first in-window evidence that sparse gossip holds quality while R grows (to 128).
- **Scaling rule hint (our inference).** In a volunteer network, memory fixes each node's local batch, so the
  global batch grows with R. Fig. 7 suggests choosing q so that q × local batch reaches a target peer batch
  (Fig. 7 spans 32–512 sequences; larger is better). Untested: the paper fixes the global batch.
- **Bandwidth check (our arithmetic with Eq. 12).** A 1B model with q = 4, δ = 3.125% and bf16 values sends about
  0.44 GB per round, which takes about 35–175 s on a 20–100 Mbit/s home uplink. Per-step gossip (H = 1, as
  tested) is therefore impossible on home links. Crowd would need H ≫ 1 (GASLoC shows dense gossip works at
  H = 30) plus low-bit values, after which the 1.5-byte indices dominate. Uploading once to a relay or object
  store for the q peers to download (as Covenant does) would cut upload cost by q. Untested for SPICE.
- **Composes with:** GASLoC's per-worker H_i (2606.11081); the β2 rule and whitening inner optimizers of
  2610.19064 (SPICE already uses the β2 rule); SparseLoCo 2-bit values (untested). Our inference: all-reduce
  inside a LAN or cluster, SPICE across the internet. At 27B a replica no longer fits a single 8–24 GB card, so it
  becomes a group of peers (bucket B2) and SPICE runs between groups.
- **Trust implications.** Messages are absolute values, so a receiver can compare each value to its own model and
  clip or trim per coordinate. But a Byzantine (malicious) peer also chooses *which* coordinates to send, and
  poisoned values spread through gossip over rounds. Selection depends on the sender's private EF state, so
  nobody can audit it. Gauntlet scoring (Covenant) and Soft Throttling (2609.39357) both assume a server. A
  gossip-native robust aggregator (for example, a trimmed mean over the contributors to each coordinate, plus
  peer reputation) is an open design problem.
- **Relation to round 1:** keeps SparseLoCo's chunked Top-k + EF but removes the hub. SOMA (2609.37899) avoids
  exchange by splitting the model into independent experts; SPICE is the opposite end, one shared model with
  cheap mixing. SOLO (2609.35440) cuts per-device memory and could, in principle, sit inside a replica.

## 6. Caveats
- **Simulated and small.** Every quality number comes from simulated replicas (up to 128 logical replicas on
  H100 nodes; OLMoE on one 8× H200 node) with H = 1; sparse gossip with H > 1 is never tested. No real WAN
  latency, churn, heterogeneous GPUs or non-IID data. Timings use 8 GPUs in one box with caps ≥ 100 Mbit/s.
- **Volume grows with R.** Near-flat replica scaling relies on q = R/2; at fixed q, loss degrades 10.3% at
  R = 128 (134M). q = R/2 is impossible at 10^6 replicas, and whether the peer-batch rule saves a fixed q is
  unknown.
- **Scale.** Global batch fixed at about 2M tokens; budgets about 20 tokens per parameter. Largest dense model
  551M (R ≤ 32 only); MoE only at R = 8.
- **Statistics.** Single seed, losses rounded to 2 decimals; gaps of 0.01–0.02 may be noise.
- **Robustness.** No Byzantine tests and no peer failures apart from the windowed deadline test.
- **Output.** The output is the average of all replicas (Algorithm 1); a real network must decide who computes
  or declares that model.
